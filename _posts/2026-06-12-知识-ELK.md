## 🎯 这是什么？

### **基础定义**
ELK Stack 是一套开源的数据处理和分析平台，由四个核心组件组成：

- **E**lasticsearch —— 分布式搜索引擎，负责存储和索引数据
- **L**ogstash —— 数据处理管道，负责收集和转换数据
- **K**ibana —— 数据可视化平台，负责展示和分析数据
- **B**eats —— 轻量级数据采集器（后来加入，扩展为 Elastic Stack）

能够安全可靠地从任何来源获取任何格式的数据，然后进行搜索、分析和可视化。

### **通俗类比**
把 ELK 想象成一个"现代化图书馆系统"：
- **Beats/Logstash**像"图书采集员"——从各地收集书籍（日志）
- **Elasticsearch**像"智能书库"——自动分类、索引，瞬间找到任何一本书
- **Kibana**像"可视化阅览室"——用图表、仪表盘展示图书内容和分析结果

### **为什么存在**
解决数据处理的四大痛点：
1. **日志分散**：数据散落在成百上千台服务器，难以统一管理
2. **搜索困难**：grep 命令在大量日志中查找效率低下
3. **分析无力**：无法从海量数据中发现趋势和规律
4. **可视化缺失**：没有直观的图表展示数据

## 🏗️ 核心原理

### **它是如何工作的**

ELK Stack 的核心架构是一个完整的数据处理流水线：

```
┌─────────────────────────────────────────────────────────────┐
│                     ELK Stack 工作流程                        │
├─────────────────────────────────────────────────────────────┤
│  📥 数据采集层 (Beats / Logstash)                           │
│     • Filebeat: 日志文件采集                                 │
│     • Metricbeat: 系统指标采集                               │
│     • Packetbeat: 网络数据采集                               │
│     • Logstash: 数据转换和丰富（ETL）                        │
│                                                              │
│  💾 数据存储层 (Elasticsearch)                               │
│     • 索引 (Index): 逻辑数据分组                             │
│     • 分片 (Shard): 数据水平分割                             │
│     • 副本 (Replica): 数据冗余备份                           │
│     • 倒排索引: 快速全文检索                                 │
│                                                              │
│  📊 数据展示层 (Kibana)                                      │
│     • Discover: 数据探索和搜索                               │
│     • Visualize: 可视化图表创建                              │
│     • Dashboard: 仪表盘                                      │
│     • Canvas: 创意画布                                      │
└─────────────────────────────────────────────────────────────┘
```

### **关键概念**

**索引（Index）**
- 专业说：Elasticsearch 中逻辑数据的最高层容器，类似关系数据库的"表"
- 通俗说："文件柜"——存放同类型文档的容器
- 命名示例：`nginx-logs-2026-06-12`、`system-metrics-2026.26`

**分片（Shard）**
- 专业说：索引的水平分割单元，分布在不同节点上
- 通俗说："文件抽屉"——把大量文件分散到多个抽屉中，提高效率
- 两种类型：
  - **主分片**：存储原始数据
  - **副本分片**：主分片的完整复制，提供冗余和查询性能

**倒排索引（Inverted Index）**
- 专业说：将文档内容拆分为词项，建立词项到文档的映射
- 通俗说："书后索引"——通过关键词快速找到内容位置
- 示例：搜索"error" → 直接定位到包含该词的所有文档

**节点（Node）与集群（Cluster）**
- **节点**：运行中的 Elasticsearch 实例
- **集群**：一个或多个节点的集合，统一管理所有数据
- 通俗理解：集群是"团队"，节点是"团队成员"

**场景 1：Nginx 访问日志分析**

- **痛点**：无法实时了解网站访问情况，攻击难以发现
- **方案**：使用 Filebeat 采集 Nginx 日志，Kibana 可视化分析

**具体实现：**
```bash
# 1. 安装 Filebeat
wget https://artifacts.elastic.co/downloads/beats/filebeat/filebeat-8.8.0-amd64.deb
dpkg -i filebeat-8.8.0-amd64.deb

# 2. 配置 Filebeat 采集 Nginx 日志
vim /etc/filebeat/filebeat.yml

# 启用 Nginx 模块
filebeat.modules:
  enabled:
    - nginx

# 配置 Nginx 日志路径
nginx.access.paths:
  - /var/log/nginx/access.log
nginx.error.paths:
  - /var/log/nginx/error.log

# 输出到 Elasticsearch
output.elasticsearch:
  hosts: ["https://192.168.1.100:9200"]
  username: "elastic"
  password: "changeme"
  ssl.verification_mode: certificate

# 设置索引名称
setup.ilm.enabled: false
setup.template.name: "nginx-logs"
setup.template.pattern: "nginx-logs-*"
output.elasticsearch.index: "nginx-logs-%{+yyyy.MM.dd}"

# 启用模块配置
filebeat setup --pipelines

# 启动 Filebeat
systemctl enable filebeat
systemctl start filebeat

# 3. 在 Kibana 创建可视化
# 打开 Kibana → Stack Management → Index Patterns
# 创建索引模式：nginx-logs-*

# 4. 创建仪表盘
# Kibana → Dashboard → Create dashboard
# 添加以下可视化：
# - 访问量趋势图
# - HTTP 状态码分布饼图
# - Top 10 访问 IP
# - 响应时间分布
# - 地理位置分布（地图）
```

- **效果**：实时监控网站访问情况，快速发现异常流量和攻击

**场景 2：应用日志集中管理**

- **痛点**：应用日志散落在多台服务器，排查问题困难
- **方案**：使用 Logstash 收集和处理多源日志

**具体实现：**
```bash
# 1. 在应用服务器部署 Filebeat
# /etc/filebeat/filebeat.yml

filebeat.inputs:
  - type: log
    enabled: true
    paths:
      - /var/log/app/*.log
    fields:
      app: myapp
      env: production
    fields_under_root: true
    multiline:
      pattern: '^[0-9]{4}-[0-9]{2}-[0-9]{2}'
      negate: true
      match: after

# 输出到 Logstash（而非直接到 ES）
output.logstash:
  hosts: ["192.168.1.200:5044"]

# 2. 在 Logstash 服务器配置处理管道
# /etc/logstash/conf.d/app-logs.conf

input {
  beats {
    port => 5044
  }
}

filter {
  # 解析 JSON 格式日志
  if [app] == "myapp" {
    json {
      source => "message"
      target => "parsed"
    }

    # 提取时间戳
    date {
      match => ["[parsed][timestamp]", "ISO8601"]
      target => "@timestamp"
    }

    # 提取日志级别
    mutate {
      add_field => {
        "log_level" => "%{[parsed][level]}"
      }
    }

    # 提取异常堆栈
    grok {
      match => {
        "message" => [
          "%{TIMESTAMP_ISO8601:timestamp} %{LOGLEVEL:level} %{GREEDYDATA:msg}",
          "Exception: %{JAVAEXCEPTION:exception}"
        ]
      }
    }
  }

  # 添加地理位置信息（如果有 IP）
  if [client_ip] {
    geoip {
      source => "[client_ip]"
      target => "[geoip]"
    }
  }
}

output {
  elasticsearch {
    hosts => ["https://192.168.1.100:9200"]
    index => "app-logs-%{[app]}-%{+yyyy.MM.dd}"
    user => "elastic"
    password => "changeme"
  }

  # 调试输出（生产环境可关闭）
  stdout { codec => rubydebug }
}

# 3. 启动服务
systemctl restart logstash
systemctl restart filebeat

# 4. 在 Kibana 搜索和分析
# 搜索特定错误：
# level: "ERROR" AND parsed.msg: "NullPointerException"

# 搜索特定时间段：
# @timestamp: [2026-06-12T00:00:00 TO 2026-06-12T23:59:59]

# 聚合分析错误类型：
# Visualize → Pie Chart → terms aggregation on parsed.exception
```

- **效果**：所有应用日志集中管理，快速搜索和定位问题

**场景 3：系统指标监控**

- **痛点**：不知道服务器资源使用情况，性能瓶颈难以发现
- **方案**：使用 Metricbeat 采集系统指标

**具体实现：**
```bash
# 1. 安装 Metricbeat
wget https://artifacts.elastic.co/downloads/beats/metricbeat/metricbeat-8.8.0-amd64.deb
dpkg -i metricbeat-8.8.0-amd64.deb

# 2. 配置 Metricbeat
vim /etc/metricbeat/metricbeat.yml

# 启用系统模块
metricbeat.modules:
  - module: system
    period: 10s
    metricsets:
      - cpu             # CPU 使用率
      - load            # 系统负载
      - memory          # 内存使用
      - network         # 网络流量
      - process         # 进程统计
      - process_summary # 进程摘要
      - core           # CPU 核心统计
      - diskio         # 磁盘 I/O
      - filesystem     # 文件系统
      - fsstat         # 文件系统统计
      - uptime         # 运行时间
      - socket         # Socket 统计
    enabled: true
    processes: ['.*']
    cpu.metrics: ["percentages"]
    core.metrics: ["percentages"]

# 输出到 Elasticsearch
output.elasticsearch:
  hosts: ["https://192.168.1.100:9200"]
  username: "elastic"
  password: "changeme"
  ssl.verification_mode: certificate

# 设置索引模板
setup.template.settings:
  index.number_of_shards: 1
  index.number_of_replicas: 1

# 启用模块配置
metricbeat setup --pipelines

# 启动服务
systemctl enable metricbeat
systemctl start metricbeat

# 3. 在 Kibana 创建监控仪表盘
# Kibana → Dashboards → 打开预置的 "System Overview" 仪表盘

# 4. 创建自定义告警（可选）
# Kibana → Stack Management → Rules and Connectors
# 创建告警规则：CPU 使用率 > 90% 持续 5 分钟
```

- **效果**：全面监控服务器性能，提前发现瓶颈

**场景 4：Docker 容器日志采集**

- **痛点**：容器日志难以收集，容器重启后日志丢失
- **方案**：使用 Filebeat 采集 Docker 容器日志

**具体实现：**
```yaml
# docker-compose.yml
version: '3'

services:
  # 应用容器
  myapp:
    image: myapp:latest
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
    volumes:
      - /var/lib/docker/containers:/var/lib/docker/containers:ro

  # Filebeat 容器
  filebeat:
    image: elastic/filebeat:8.8.0
    user: root
    volumes:
      - ./filebeat.yml:/usr/share/filebeat/filebeat.yml:ro
      - /var/lib/docker/containers:/var/lib/docker/containers:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
    command: filebeat -e -strict.perms=false
    depends_on:
      - myapp

# filebeat.yml 配置
filebeat.inputs:
  - type: container
    enabled: true
    paths:
      - '/var/lib/docker/containers/*/*.log'
    processors:
      - add_docker_metadata:
          host: "unix:///var/run/docker.sock"
      - decode_json_fields:
          fields: ["message"]
          target: "json"
          overwrite_keys: true

output.elasticsearch:
  hosts: ["https://elasticsearch:9200"]
  username: "elastic"
  password: "changeme"
  ssl.verification_mode: none

setup.kibana:
  host: "https://kibana:5601"

# 启动
docker-compose up -d

# 在 Kibana 查看日志
# 可以看到容器的元数据（容器名、镜像、标签等）
```

- **效果**：容器日志统一收集，容器重启也不丢失历史日志
