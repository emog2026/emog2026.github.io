# Kubernetes 控制面与数据面组件详解

## 架构概览

Kubernetes 集群采用主从架构，分为两个主要部分：

- **控制面**：负责集群的决策和管理
- **数据面**：负责运行实际的工作负载

```
┌─────────────────────────────────────────────────────────┐
│                    控制平面                    │

│  └────┬────┘  └────┬────┘  └────┬────┘  └────┬────┘  │

        └──────────┴──────────┴───────────┘
                     │
┌────────────────────┼────────────────────────────────────┐
│                    数据面                   │
│  ┌─────────┐          ┌─────────┐          ┌─────────┐  │
│  │  Node 1 │          │  Node 2 │          │  Node N │  │
│  │┌───────┐│          │┌───────┐│          │┌───────┐│  │
```

## 控制面组件

### 1. API Server (kube-apiserver)

**作用**：集群的统一入口，所有内部组件和外部用户都通过 API Server 与集群交互。

**核心功能**：

| 功能 | 描述 |
|------|------|
| **认证鉴权** | 验证用户身份，检查操作权限 |
| **准入控制** | 对请求进行额外验证和修改 |
| **状态协调** | 将用户请求持久化到 etcd |
| **数据聚合** | 聚合所有组件的状态信息 |

**特点**：
- 无状态服务，可水平扩展
- 唯一连接 etcd 的组件
- 提供 REST API 和 gRPC 接口

### 2. etcd

**作用**：集群的键值数据库，存储所有集群状态数据。

**核心功能**：

| 功能 | 描述 |
|------|------|
| **数据存储** | 存储配置数据、状态信息、持久化数据 |
| **Watch 机制** | 提供变更通知，支持事件驱动 |
| **分布式一致性** | 基于 Raft 协议保证数据一致性 |
| **高可用** | 支持多节点集群部署 |

**数据类型**：
- Pod/Service/Deployment 等资源定义
- 集群配置信息
- 持久化卷声明
- 秘钥和配置数据

### 3. Scheduler (kube-scheduler)

**作用**：负责将新创建的 Pod 调度到合适的节点上运行。

**调度流程**：

```
1. 监听未调度的 Pod
       ↓
2. 过滤节点
   - 资源是否足够
   - 节点选择器匹配
   - 亲和/反亲和规则
   - 污点和容忍
       ↓
3. 打分排序
   - 资源利用率
   - 镜像本地存在
   - 数据本地性
   - 节点负载
       ↓
4. 绑定节点
   - 更新 Pod 的 nodeName
   - 写入 etcd
```

**调度策略**：

| 策略 | 说明 |
|------|------|
| **资源限制** | CPU、内存、存储请求与限制 |
| **节点选择器** | 通过标签选择特定节点 |
| **亲和性规则** | Pod 间亲和/反亲和 |
| **污点容忍** | 控制Pod可调度到哪些节点 |
| **优先级** | 支持Pod优先级和抢占 |

### 4. Controller Manager (kube-controller-manager)

**作用**：运行多个控制器进程，维护集群的期望状态。

**主要控制器**：

| 控制器 | 功能 |
|--------|------|
| **Node Controller** | 监控节点状态，处理故障节点 |
| **Replication Controller** | 保证副本数量符合预期 |
| **Deployment Controller** | 管理 Deployment 的滚动更新 |
| **StatefulSet Controller** | 管理有状态应用 |
| **DaemonSet Controller** | 保证每个节点运行一个Pod |
| **Job/CronJob Controller** | 管理批处理任务 |
| **Service Account Controller** | 管理服务账号 |
| **Namespace Controller** | 管理命名空间生命周期 |
| **Endpoint Controller** | 维护 Service 后端端点列表 |
| **Service Controller** | 负载均衡器路由同步 |

**工作原理**：
```
┌─────────────────────────────────────────────┐
│          控制循环         │
│                                             │
│   1. Watch API Server 获取资源变化          │
│              ↓                              │
│   2. 对比当前状态与期望状态                  │
│              ↓                              │
│   3. 执行协调操作使两者一致                  │
│              ↓                              │
│   4. 更新 API Server 中的资源状态            │
│              ↓                              │
│   5. 循环执行                                │
└─────────────────────────────────────────────┘
```

### 5. Cloud Controller Manager

**作用**：将特定于云平台的逻辑与 Kubernetes 核心代码解耦。

**主要控制器**：

| 控制器 | 功能 |
|--------|------|
| **Node Controller** | 更新节点标签，删除云节点 |
| **Route Controller** | 配置云平台路由 |
| **Service Controller** | 创建云负载均衡器 |
| **Volume Controller** | 创建/附加/挂载云存储卷 |

## 数据面组件

### 1. Kubelet

**作用**：节点代理，负责管理本节点上的 Pod 和容器。

**核心功能**：

| 功能 | 描述 |
|------|------|
| **Pod 管理** | 根据 PodSpec 创建和管理容器 |
| **健康检查** | 定期执行探针检查容器健康状态 |
| **状态上报** | 向 API Server 汇报节点和 Pod 状态 |
| **卷管理** | 挂载和卸载存储卷 |
| **镜像管理** | 拉取和管理容器镜像 |
| **资源监控** | 通过 cgroups 监控和限制资源使用 |

**工作流程**：

```
1. 从 API Server 获取分配到本节点的 Pod
       ↓
2. 向容器运行时下发容器创建命令
       ↓
3. 监控容器运行状态，执行健康检查
       ↓
4. 定期向 API Server 上报节点和 Pod 状态
       ↓
5. 执行容器生命周期操作（启动、停止、重启）
```

### 2. Kube-proxy

**作用**：维护节点上的网络规则，实现 Service 的负载均衡和网络代理。

**工作模式**：

| 模式 | 说明 | 性能 |
|------|------|------|
| **Userspace** | 用户空间代理，效率低 | 低 |
| **iptables** | 内核空间，基于规则匹配 | 中 |
| **IPVS** | 内核空间，基于哈希表，高性能 | 高 |

**核心功能**：

| 功能 | 描述 |
|------|------|
| **服务发现** | 监听 Service 和 Endpoints 变化 |
| **负载均衡** | 在多个后端 Pod 间分发流量 |
| **网络代理** | 处理 ClusterIP、NodePort、ExternalIP |
| **会话保持** | 支持基于客户端 IP 的会话亲和 |

**iptables/IPVS 规则示例**：
```
Service: my-service (ClusterIP: 10.96.0.100)
    ↓
Kube-proxy 创建规则
    ↓
流量到达 10.96.0.100:80
    ↓
规则匹配 → DNAT 到某个后端 Pod
    ↓
Pod IP: 10.244.1.5:8080
Pod IP: 10.244.2.8:8080
Pod IP: 10.244.3.2:8080
```

### 3. Container Runtime

**作用**：负责下载镜像和运行容器。

**支持的运行时**：

| 运行时 | 类型 | 状态 |
|--------|------|------|
| **containerd** | CRI | 推荐使用 |
| **CRI-O** | CRI | 推荐使用 |
| **Docker Engine** | Docker shim | 已弃用 |

**CRI (Container Runtime Interface)**：

```
┌───────────────────────────────────────┐
│          Kubelet                       │
└───────────────┬───────────────────────┘
                │ gRPC
                ↓
┌───────────────────────────────────────┐
│       CRI (Container Runtime           │
│       Interface) 插件层                │
│  ┌─────────┐      ┌─────────┐        │
│  │ Image   │      │ Runtime │        │
│  │ Service │      │ Service │        │
│  └─────────┘      └─────────┘        │
└───────────────┬───────────────────────┘
                │
                ↓
┌───────────────────────────────────────┐
│     Container Runtime (containerd)    │
│  ┌─────────┐      ┌─────────┐        │
│  │ 镜像    │      │ 容器    │        │
│  │ 管理    │      │ 执行    │        │
│  └─────────┘      └─────────┘        │
└───────────────────────────────────────┘
```

## 组件交互流程

### Pod 创建完整流程

```
┌─────────────────────────────────────────────────────────────┐
│                     Pod 创建流程                              │
└─────────────────────────────────────────────────────────────┘

1. 用户提交请求
   kubectl create -f pod.yaml
         ↓
2. API Server 处理
   - 认证鉴权
   - 准入控制
   - 持久化到 etcd
         ↓
3. Scheduler 监听到未调度的 Pod
   - 执行调度算法
   - 选择最优节点
   - 绑定节点信息
         ↓
4. Kubelet 监听到分配给自己的 Pod
   - 从 API Server 获取 Pod Spec
   - 调用 CRI 运行时拉取镜像
   - 创建并启动容器
   - 执行健康检查
         ↓
5. Kube-proxy 配置网络规则
   - 创建 iptables/IPVS 规则
   - 配置 Service 路由
         ↓
6. Controller Manager 监控状态
   - 确保副本数量
   - 处理异常情况
```

## 总结

| 层面 | 组件 | 核心职责 |
|------|------|----------|
| **控制面** | API Server | 统一入口，认证鉴权，协调各组件 |
| **控制面** | etcd | 数据存储，状态管理 |
| **控制面** | Scheduler | Pod 调度，资源分配 |
| **控制面** | Controller Manager | 维护期望状态，自动修复 |
| **控制面** | Cloud Controller Manager | 云平台集成 |
| **数据面** | Kubelet | Pod 生命周期管理，状态上报 |
| **数据面** | Kube-proxy | 网络代理，负载均衡 |
| **数据面** | Container Runtime | 容器运行，镜像管理 |

**设计原则**：

1. **声明式 API**：用户声明期望状态，系统自动实现
2. **控制器模式**：持续循环，确保实际状态向期望状态收敛
3. **松耦合**：各组件通过 API Server 解耦，独立演化
4. **可扩展性**：支持自定义控制器和调度策略
5. **高可用**：控制面多副本，数据面可水平扩展
