---

🎯 **它是做什么的？**

Flash-promoter 是一个"内容翻译工厂"。想象一下：
- 你写一篇技术文章 → 它自动生成适合公众号的长文、知乎的问答风格、B站的专栏标题、小红书的笔记正文
- 不需要登录云端，所有处理都在你本地完成
- AI 生成的版本需要你确认后才能发布，保证内容安全

**核心价值：本地优先 + 插件化架构**
- 你的内容永远在你的设备上，不依赖云服务
- 新增平台就像装插件，不需要改动核心代码

---

🔑 **核心概念解读**

**CanonicalPost（统一内容模型）**
- 专业说：支持 7 种 Block 类型的标准化内容模型
- 通俗说：就像把文章拆成乐高积木（段落、标题、图片、代码等），每个平台按需重新组合

**PlatformAdapter（平台适配器）**
- 专业说：插件化的平台内容转换器
- 通俗说：每个平台有一个"翻译员"，把你的文章翻译成那个平台的"方言"

**发布模式**
- simulate（模拟）：假装发布，测试用
- draft（草稿）：生成草稿格式
- assist（辅助）：生成带提示的辅助内容
- publish（真实发布）：预留接口，需二次确认

---

💡 **切实可落地的例子**

**场景 1：独立技术博主**
- **痛点**：写一篇技术文章要手动改 4 个版本，公众号要长文、知乎要问答、B 站要吸引眼球标题
- **解决方案**：用 Flash-promoter 输入 Markdown → 自动生成四个平台版本 → 在预览标签页切换查看
- **具体步骤**：
  ```bash
  npm install
  npm run dev
  # 打开 http://localhost:5173
  # 点击"载入示例内容"或粘贴自己的 Markdown
  # 切换四个平台预览标签页查看适配结果
  ```
- **效果**：从 2 小时手动改编变成 10 分钟确认修改

---

**场景 2：自媒体小团队（2-3 人）**
- **痛点**：内容要发多个平台，团队成员风格不统一，容易出错
- **解决方案**：用 Flash-promoter 的统一模型保证内容一致性，通过 AI 生成后人工确认
- **具体步骤**：
  ```bash
  npm run dev
  # 在本地 API 服务 (:3333) 管理所有发布记录
  # SQLite 数据库保存在 data/ 目录
  # 运行 npm run test:acceptance 验证完整流程
  ```
- **效果**：团队协作有据可查，发布历史可追溯

---

**场景 3：工具开发者验证场景**
- **痛点**：想验证自己平台的内容适配逻辑，需要可复现的测试环境
- **解决方案**：使用 Mock 适配器 + 模拟发布模式完整跑通流程
- **具体步骤**：
  ```bash
  npm run test:acceptance
  # 自动运行 10+ 步验收测试
  # 包括：输入 → 适配 → 预览 → 校验 → 模拟发布
  ```
- **效果**：5 分钟验证完整发布管线，无需真实账号

---

👥 **适合谁用？**

✅ 经常在多个平台发布内容的创作者
✅ 需要本地优先、数据安全敏感的团队
✅ 验证内容分发工具链的开发者
❌ 只发单一平台的人（用官方编辑器更简单）
❌ 需要云端协作的远程团队（目前本地模式）

⚠️ **注意事项**

- **当前 MVP 阶段不会真实发布**：所有操作在本地完成，`publish` 模式预留但需二次确认
- **技术要求**：需要 Node.js >= 24，npm >= 11
- **开源协议**：MIT 协议，可商用
- **学习曲线**：⭐⭐⭐☆☆（需要了解 Markdown、本地开发环境）
- **替代方案**：各平台官方编辑器、云端发布工具（如易撰、壹伴）
