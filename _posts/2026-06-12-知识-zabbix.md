## 🎯 这是什么？

### **基础定义**
Zabbix 是一个企业级开源分布式监控解决方案，能够监控各种网络参数、服务器健康状况和应用性能，提供灵活的通知机制让运维人员快速响应问题。

- 由 **Alexei Vladishev** 创建，1998年起步，2004年发布首个正式版本
- 基于 GPL 协议开源，完全免费
- 采用 LAMP 架构（Linux + Apache + MySQL + PHP）
- 支持分布式架构，可监控数千台设备

### **通俗类比**
把 Zabbix 想象成"医院的重症监护室"：
- **监控项**：像心率监测仪——持续测量各项指标（CPU、内存、磁盘）
- **触发器**：像报警阈值设置——指标异常时触发告警
- **告警**：像呼叫医生——通过短信、邮件、微信通知运维人员
- **仪表盘**：像病房大屏幕——集中展示所有设备的健康状态

### **为什么存在**
解决 IT 运维的四大痛点：
1. **被动救火**：系统挂了才知道，影响业务
2. **盲区监控**：不知道服务器、网络、应用的实时状态
3. **告警延迟**：发现问题太晚，错过最佳处理时机
4. **数据孤岛**：没有历史数据，无法分析趋势

## 🏗️ 核心原理

### **它是如何工作的**

Zabbix 的核心架构包括 **Server、Agent、Proxy、Database、Web Frontend**，典型工作流程：

```
┌─────────────────────────────────────────────────────────────┐
│                     Zabbix 工作流程                           │
├─────────────────────────────────────────────────────────────┤
│  📊 数据采集层                                                │
│     • Zabbix Agent (被动模式): 等待 Server 请求，返回数据      │
│     • Zabbix Agent (主动模式): 主动采集数据并推送到 Server    │
│     • SNMP/IPMI/JMX: 监控网络设备、硬件、Java应用             │
│     • HTTP/HTTPS: 监控Web服务可用性                          │
│                                                              │
│  🔧 核心处理层 (Zabbix Server)                               │
│     • 接收并处理所有监控数据                                  │
│     • 计算触发器表达式，判断是否告警                          │
│     • 管理告警发送和执行动作                                  │
│                                                              │
│  💾 数据存储层 (Database)                                    │
│     • 配置信息: 主机、监控项、触发器等配置                     │
│     • 历史数据: 每个采集到的原始值                            │
│     • 趋势数据: 按小时聚合的历史数据                          │
│                                                              │
│  🖥️ 展示与交互层 (Web Frontend)                              │
│     • 仪表盘可视化展示                                        │
│     • 监控配置管理                                            │
│     • 告警确认和处理                                          │
└─────────────────────────────────────────────────────────────┘
```

### **关键概念**

**监控项（Item）**
- 专业说：Zabbix 采集的单个指标，由 key 唯一标识
- 通俗说："温度计"——测量一个具体数值（如 CPU 使用率）
- 示例：`system.cpu.load[percpu,avg1]` - 每CPU核心1分钟平均负载

**触发器（Trigger）**
- 专业说：定义监控项何时触发的逻辑表达式
- 通俗说："报警规则"——设定什么情况下需要告警
- 示例：`system.cpu.load.last() > 5` - CPU负载大于5时触发

**模板（Template）**
- 专业说：一组可复用的监控项、触发器、图形等配置
- 通俗说："体检套餐"——预定义的监控方案
- 示例：`Template OS Linux` - Linux 主机标准监控模板

**Zabbix Proxy**
- 专业说：分布式监控架构中的代理组件，收集数据后统一发送到 Server
- 通俗说："地区分公司"——在远程位置收集数据，减轻中心压力

**主动模式 vs 被动模式**
- **被动模式**：Server 主动问 Agent 要数据（默认）
- **主动模式**：Agent 主动推送数据到 Server（适合防火墙环境）

**场景 1：Linux 服务器基础监控**

- **痛点**：不知道服务器 CPU、内存、磁盘使用情况，服务器挂了才发现
- **方案**：使用 Zabbix 官方模板快速部署监控

**具体实现：**
```bash
# 1. 安装 Zabbix Agent
wget https://repo.zabbix.com/zabbix/6.0/ubuntu/pool/main/z/zabbix-release/zabbix-release_6.0-4+ubuntu22.04_all.deb
dpkg -i zabbix-release_6.0-4+ubuntu22.04_all.deb
apt update
apt install zabbix-agent

# 2. 配置 Agent
vim /etc/zabbix/zabbix_agentd.conf
# 修改以下配置：
Server=192.168.1.100          # Zabbix Server IP
ServerActive=192.168.1.100    # 主动模式地址
Hostname=web-server-01        # 主机名，需与 Zabbix Server 配置一致

# 3. 启动 Agent
systemctl enable zabbix-agent
systemctl start zabbix-agent

# 4. 在 Zabbix Server 端添加主机
# Web 界面：配置 → 主机 → 创建主机
# - 主机名称：web-server-01
# - 群组：Linux servers
# - 接口：Agent 192.168.1.101:10050
# - 模板：Template OS Linux by Zabbix Agent

# 5. 查看监控数据
# 监控 → 最新数据 → 选择主机 → 查看各项指标
```

- **效果**：实时监控 CPU、内存、磁盘、网络等指标，异常自动告警

**场景 2：Nginx 状态监控**

- **痛点**：不知道 Web 服务请求量、响应时间、连接数
- **方案**：配置 Nginx stub_status 模块，自定义监控项

**具体实现：**
```nginx
# 1. 启用 Nginx status 模块
vim /etc/nginx/conf.d/status.conf

server {
    listen 127.0.0.1:80;
    server_name _;
    
    location /nginx_status {
        stub_status on;
        access_log off;
        allow 127.0.0.1;
        deny all;
    }
}

# 重载配置
nginx -t && nginx -s reload

# 2. 测试访问
curl http://127.0.0.1/nginx_status
# 输出：
# Active connections: 2
# server accepts handled requests
#  12345 12345 123456
# Reading: 0 Writing: 1 Waiting: 1

# 3. 创建自定义监控脚本
vim /etc/zabbix/scripts/nginx_status.sh
#!/bin/bash
# nginx_status.sh - 获取 Nginx 状态指标

case "$1" in
    active)
        curl -s http://127.0.0.1/nginx_status | awk '/Active/ {print $3}'
        ;;
    accepts)
        curl -s http://127.0.0.1/nginx_status | awk 'NR==3 {print $1}'
        ;;
    handled)
        curl -s http://127.0.0.1/nginx_status | awk 'NR==3 {print $2}'
        ;;
    requests)
        curl -s http://127.0.0.1/nginx_status | awk 'NR==3 {print $3}'
        ;;
    reading)
        curl -s http://127.0.0.1/nginx_status | awk 'NR==4 {print $2}'
        ;;
    writing)
        curl -s http://127.0.0.1/nginx_status | awk 'NR==4 {print $4}'
        ;;
    waiting)
        curl -s http://127.0.0.1/nginx_status | awk 'NR==4 {print $6}'
        ;;
    *)
        echo "Usage: $0 {active|accepts|handled|requests|reading|writing|waiting}"
        exit 1
        ;;
esac

# 添加执行权限
chmod +x /etc/zabbix/scripts/nginx_status.sh

# 4. 配置 Zabbix Agent 自定义监控项
vim /etc/zabbix/zabbix_agentd.conf
# 添加以下内容：
UserParameter=nginx.status[*],/etc/zabbix/scripts/nginx_status.sh $1

# 重启 Agent
systemctl restart zabbix-agent

# 5. 在 Zabbix Server 创建监控项
# 监控项名称：Nginx Active Connections
# 键值：nginx.status[active]
# 数据类型：Numeric (unsigned)
# 更新间隔：60s

# 6. 创建触发器
# 名称：Too many active connections on Nginx
# 表达式：last(nginx.status[active]) > 1000
# 严重性：警告
```

- **效果**：实时监控 Nginx 连接数、请求数，异常时自动告警

**场景 3：MySQL 数据库监控**

- **痛点**：数据库性能问题不知道，慢查询、连接数异常才发现
- **方案**：使用官方 MySQL 模板或 Percona 插件

**具体实现：**
```bash
# 方案一：使用官方模板（简单）

# 1. 创建监控用户
mysql -uroot -p <<EOF
CREATE USER 'zabbix'@'localhost' IDENTIFIED BY 'secure_password';
GRANT USAGE,REPLICATION CLIENT,PROCESS,SHOW DATABASES,SHOW VIEW ON *.* TO 'zabbix'@'localhost';
FLUSH PRIVILEGES;
EOF

# 2. 配置 Zabbix Agent
vim /etc/zabbix/zabbix_agentd.conf
# 添加 MySQL 配置：
UserParameter=mysql.ping[*],mysqladmin -h$1 -P$2 ping
UserParameter=mysql.getVariableVariables[*],mysql -h$1 -P$2 -e "show VARIABLES"

# 3. 在 Zabbix Web 界面
# - 添加主机
# - 链接模板：Template DB MySQL by Zabbix Agent
# - 配置宏：{$MYSQL_HOST}、{$MYSQL_PORT}、{$MYSQL_USER}、{$MYSQL_PASSWORD}

# 方案二：使用 Percona 插件（功能更全）

# 1. 安装 Percona 插件
apt install percona-zabbix-templates

# 2. 复制脚本
cp /var/lib/zabbix/percona/scripts/mysql_monitoring.sh /etc/zabbix/scripts/
chmod +x /etc/zabbix/scripts/mysql_monitoring.sh

# 3. 配置 Agent
vim /etc/zabbix/zabbix_agentd.conf
Include=/var/lib/zabbix/percona/templates/userparameter_percona_mysql.conf

# 4. 创建配置文件
vim /var/lib/zabbix/percona/.my.cnf
[mysql]
host=localhost
user=zabbix
password=secure_password
socket=/var/run/mysqld/mysqld.sock

# 5. 导入模板
# Zabbix Web → 配置 → 模板 → 导入
# 选择 percona_mysql_template.xml

# 6. 查看监控指标
# 监控项包括：QPS、TPS、连接数、缓冲池命中率、慢查询数量等
```

- **效果**：全面监控数据库性能，提前发现瓶颈

**场景 4：网络设备 SNMP 监控**

- **痛点**：交换机、路由器、防火墙状态不可见，网络故障难以定位
- **方案**：通过 SNMP 协议监控网络设备

**具体实现：**
```bash
# 1. 配置网络设备 SNMP（以 Cisco 交换机为例）
enable
conf t
# 创建 SNMP 园区
snmp-server community public RO
snmp-server community private RW
# 允许的 Zabbix Server IP
snmp-server host 192.168.1.100 public
# 启用 SNMP
snmp-server enable traps
end
wr

# 2. 测试 SNMP 连接
# 在 Zabbix Server 安装 SNMP 工具
apt install snmp snmp-mibs-downloader

# 测试获取设备信息
snmpwalk -v 2c -c public 192.168.1.1 system
snmpwalk -v 2c -c public 192.168.1.1 IF-MIB::ifDescr

# 3. 在 Zabbix Web 添加网络设备
# 配置 → 主机 → 创建主机
# - 主机名称：Core-Switch-01
# - 群组：Network Devices
# - 接口：SNMPv2
#   - IP地址：192.168.1.1
#   - 端口：161
#   - SNMP community：public
# - 模板：Template Net Cisco SNMP

# 4. 自定义 SNMP 监控项示例
# 监控项名称：Interface eth0/1 input traffic
# 键值：net.if.in[eth0/1]
# 类型：SNMP agent
# SNMP OID：1.3.6.1.2.1.2.2.1.10.10101
# 数据类型：Numeric (unsigned)
# 单位：bps
# 存储值：Delta (speed per second)

# 5. 创建触发器示例
# 名称：High traffic on interface eth0/1
# 表达式：last(net.if.in[eth0/1]) > 10000000000
# 严重性：高
# 说明：入口流量超过 10Gbps

# 6. 网络拓扑图
# 监控 → 拓扑图 → 创建网络拓扑
# 添加交换机图标，连接线显示链路状态和流量
```

- **效果**：实时监控网络设备端口状态、流量、错误率，快速定位网络故障

| **社区** | 活跃的全球社区 | 中文资料相对较少 |
| **学习** | 配置相对简单 | 深入功能需要时间 |
