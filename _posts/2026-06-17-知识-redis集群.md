# 📌 一句话总结
数据自动分片到多台服务器，单台故障不影响整体服务

## 🎯 这是什么？

### 基础定义
Redis 集群是一种分布式缓存解决方案，将数据自动分散到多个 Redis 节点，实现横向扩展和高可用。

### 通俗类比
想象一个大型图书馆：
- **单机 Redis**：一个房间放所有书，找书快但放不下
- **Redis 集群**：多个房间分门别类放书，每个房间有人负责，一个房间着火不影响其他房间

### 为什么存在
解决四个核心问题：
1. **容量限制**：单机内存不够（几十 GB 到 TB 级）
2. **性能瓶颈**：单机 QPS 有限（10 万级需求）
3. **单点故障**：一台挂了全部挂
4. **数据安全**：需要数据副本和自动故障转移

## 🏗️ 核心原理

### Redis Cluster 工作机制

```
                    客户端
                       │
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   ┌────▼────┐    ┌────▼────┐   ┌────▼────┐
   │ Node 1  │    │ Node 2  │   │ Node 3  │
   │ Master  │    │ Master  │   │ Master  │
   │ 0-5460  │    │ 5461-10922│ 10923-16383│
   └────┬────┘    └────┬────┘   └────┬────┘
        │              │              │
        │ Replica      │ Replica      │ Replica
   ┌────▼────┐    ┌────▼────┐   ┌────▼────┐
   │Node 1'   │    │Node 2'   │   │Node 3'   │
   │  Slave   │    │  Slave   │   │  Slave   │
   └──────────┘    └──────────┘   └──────────┘

   16384 个槽位（Hash Slots）
   数据通过 CRC16(key) % 16364 决定去哪个节点
```

### 关键概念

**Hash Slot（哈希槽）**
- 专业说：Redis 集群将数据空间划分为 16384 个槽位
- 通俗说：把 16384 个抽屉分给不同柜子，数据根据规则放进对应抽屉

**分片策略**
```python
# 计算键所在的槽位
slot = CRC16(key) % 16384

# 示例：
# key: "user:1001" → slot: 2345 → Node 1
# key: "order:5002" → slot: 8901 → Node 2
```

**主从复制**
- 每个主节点可以有多个从节点
- 主节点故障时，从节点自动提升为主节点
- 集群要求至少 3 个主节点才能高可用

**Gossip 协议**
- 节点之间定期交换状态信息
- 自动发现故障节点
- 无中心架构，所有节点平等

**重定向（Redirection）**
```bash
# 客户请求到错误的节点
GET user:1001

# 节点返回：
-MOVED 2345 192.168.1.101:6379

# 客户端自动重定向到正确节点
```

### 节点状态

| 状态 | 说明 |
|------|------|
| Master | 主节点，负责处理分配的槽位 |
| Slave | 从节点，复制主节点数据 |
| Fail | 故障节点，不处理请求 |
| Noaddr | 节点地址未知 |

**主流方案对比**：

| 方案 | 特点 | 适用场景 |
|------|------|----------|

## 💼 应用场景

### 场景 1：高并发缓存 - 电商平台

**痛点**：
- 双十一 QPS 突破 50 万
- 单机 Redis 扛不住，内存也满了

**方案**：
6 节点 Redis Cluster（3 主 3 从）

**具体实现**：

```bash
# 创建配置目录
mkdir -p /opt/redis-cluster/{7001,7002,7003,7004,7005,7006}

# 生成配置文件（以 7001 为例）
cat > /opt/redis-cluster/7001/redis.conf <<EOF
port 7001
cluster-enabled yes
cluster-config-file nodes-7001.conf
cluster-node-timeout 5000
appendonly yes
appendfilename "appendonly-7001.aof"
dbfilename dump-7001.rdb
dir /opt/redis-cluster/7001
EOF

# 复制并修改其他节点配置
for port in 7002 7003 7004 7005 7006; do
  cp /opt/redis-cluster/7001/redis.conf /opt/redis-cluster/$port/
  sed -i "s/7001/$port/g" /opt/redis-cluster/$port/redis.conf
done

# 启动所有节点
for port in 7001 7002 7003 7004 7005 7006; do
  redis-server /opt/redis-cluster/$port/redis.conf
done

# 创建集群（3 主 3 从）
redis-cli --cluster create \
  192.168.1.101:7001 \
  192.168.1.101:7002 \
  192.168.1.101:7003 \
  192.168.1.101:7004 \
  192.168.1.101:7005 \
  192.168.1.101:7006 \
  --cluster-replicas 1

# 验证集群状态
redis-cli -c -p 7001 cluster info
# cluster_state:ok 表示集群正常
```

```python
# Python 客户端连接
import redis

# 使用 redis-py-cluster 或 redis-py (支持集群模式)
r = redis.RedisCluster(
    host='192.168.1.101',
    port=7001,
    decode_responses=True
)

# 自动重定向到正确的节点
r.set('user:1001', '{"name": "Alice"}')
user = r.get('user:1001')
```

**效果**：
- QPS 提升 6 倍
- 内存容量扩展 6 倍
- 单节点故障自动切换

### 场景 2：地理分布部署 - 全球游戏

**痛点**：
- 玩家遍布全球，访问延迟高
- 需要跨区域数据同步

**方案**：
多地域 Redis Cluster + 定期同步

**具体实现**：

```bash
# 美国区域集群
redis-cli --cluster create \
  us-east-1-a:7001 \
  us-east-1-b:7002 \
  us-east-1-c:7003 \
  --cluster-replicas 1

# 欧洲区域集群
redis-cli --cluster create \
  eu-west-1-a:7001 \
  eu-west-1-b:7002 \
  eu-west-1-c:7003 \
  --cluster-replicas 1

# 亚洲区域集群
redis-cli --cluster create \
  ap-southeast-1-a:7001 \
  ap-southeast-1-b:7002 \
  ap-southeast-1-c:7003 \
  --cluster-replicas 1
```

```bash
# 使用 redis-shake 进行数据同步
wget https://github.com/alibaba/redis-shake/releases/download/v2.0.3/redis-shake-v2.0.3.tar.gz
tar -xzf redis-shake-v2.0.3.tar.gz

# 配置同步
cat > shake.conf <<EOF
source.type = standalone
source.address = us-east-1-a:6379
source.password = your_password

target.type = cluster
target.address = eu-west-1-a:6379
target.password = your_password

sync_mode = incremental
EOF

# 启动同步
./redis-shake -conf=shake.conf
```

**效果**：
- 玩家就近访问，延迟 < 50ms
- 跨区域定期同步数据一致性

### 场景 3：高可用哨兵模式 - 金融系统

**痛点**：
- 金融业务要求高可用
- 主库故障秒级切换

**方案**：
Redis Sentinel 哨兵模式

**具体实现**：

```ini
# 主库配置 redis-master.conf
port 6379
bind 0.0.0.0
requirepass your_password
masterauth your_password
appendonly yes
```

```ini
# 从库配置 redis-slave.conf
port 6380
bind 0.0.0.0
requirepass your_password
masterauth your_password
replicaof 192.168.1.100 6379
appendonly yes
```

```ini
# 哨兵配置 sentinel.conf
port 26379
sentinel monitor mymaster 192.168.1.100 6379 2
sentinel auth-pass mymaster your_password
sentinel down-after-milliseconds mymaster 5000
sentinel parallel-syncs mymaster 1
sentinel failover-timeout mymaster 10000
```

```bash
# 启动主库
redis-server /etc/redis/redis-master.conf

# 启动两个从库
redis-server /etc/redis/redis-slave1.conf
redis-server /etc/redis/redis-slave2.conf

# 启动三个哨兵
redis-sentinel /etc/redis/sentinel1.conf
redis-sentinel /etc/redis/sentinel2.conf
redis-sentinel /etc/redis/sentinel3.conf

# 验证哨兵状态
redis-cli -p 26379 sentinel master mymaster
```

```python
# Python 客户端使用 Sentinel
from redis.sentinel import Sentinel

sentinel = Sentinel([
    ('192.168.1.101', 26379),
    ('192.168.1.102', 26379),
    ('192.168.1.103', 26379)
], socket_timeout=0.5)

# 自动获取主库地址
master = sentinel.master_for('mymaster', socket_timeout=0.5)

# 自动获取从库地址进行读操作
slave = sentinel.slave_for('mymaster', socket_timeout=0.5)

# 写操作（主库）
master.set('balance:1001', '10000')

# 读操作（从库）
balance = slave.get('balance:1001')
```

**效果**：
- 主库故障 10 秒内自动切换
- 客户端自动连接新主库
- 数据零丢失

### 场景 5：Kubernetes 部署生产集群

**痛点**：
- 生产环境需要自动扩缩容
- 节点故障自动恢复

**方案**：
使用 Redis Operator 管理集群

**具体实现**：

```yaml
# redis-cluster.yaml
apiVersion: redis.redis.op/v1alpha1
kind: RedisCluster
metadata:
  name: redis-cluster
spec:
  size: 6  # 6 个节点（3 主 3 从）
  image: redis:7-alpine
  resources:
    requests:
      cpu: 500m
      memory: 1Gi
    limits:
      cpu: 2000m
      memory: 4Gi
  storage:
    size: 10Gi
    storageClassName: fast-ssd
  redisConfig:
    maxmemory-policy: allkeys-lru
    appendonly: "yes"
```

```bash
# 安装 Redis Operator
kubectl apply -f https://raw.githubusercontent.com/spotahome/redis-operator/master/manifests/databases.spotahome.com_redisclusters.yaml

# 部署集群
kubectl apply -f redis-cluster.yaml

# 查看集群状态
kubectl get rediscluster

# 查看 Pod 状态
kubectl get pods -l redis-cluster=redis-cluster

# 连接测试
kubectl exec -it redis-cluster-0-0 -- redis-cli -c
```

**效果**：
- 自动故障恢复
- 支持滚动升级
- 持久化存储自动管理

## ⚖️ 优缺点分析

| 维度 | ✅ 优点 | ❌ 缺点/局限性 |
|------|---------|---------------|
| 性能 | 分布式横向扩展 | 客户端需要支持集群 |
| 可用性 | 自动故障转移 | 槽位迁移有短暂抖动 |
| 扩展性 | 动态添加节点 | 扩缩容需要手动触发 |
| 数据安全 | 多副本自动复制 | 异步复制可能丢数据 |
| 运维成本 | 去中心化简单 | 监控和调试复杂 |

**Redis Cluster vs Sentinel 对比**：

| 特性 | Redis Cluster | Sentinel |
|------|---------------|----------|
| 架构 | 去中心化 | 主从 + 哨兵监控 |
| 数据分片 | 自动 | 需要客户端 |
| 节点数 | 至少 3 主 3 从 | 1 主 N 从 |
| 扩展性 | 水平扩展 | 垂直扩展 |
| 复杂度 | 中等 | 简单 |

## 🔍 常见问题排查

### 集群状态检查

```bash
# 查看集群状态
redis-cli -c -p 7001 cluster info

# 关键字段：
# cluster_state:ok          # 集群状态
# cluster_slots_assigned:16384  # 已分配槽位
# cluster_known_nodes:6     # 已知节点数
```

### 节点状态检查

```bash
# 查看所有节点
redis-cli -c -p 7001 cluster nodes

# 输出示例：
# 1a2b3c... 192.168.1.101:7001@17001 master - 0 123456789 connected 0-5460
# 4d5e6f... 192.168.1.102:7002@17002 master - 0 123456789 connected 5461-10922
# 7g8h9i... 192.168.1.103:7003@17003 slave 1a2b3c... 0 123456789 connected
```

### 槽位迁移

```bash
# 将槽位从一个节点迁移到另一个节点
redis-cli --cluster reshard 192.168.1.101:7001 \
  --cluster-from 1a2b3c... \
  --cluster-to 4d5e6f... \
  --cluster-slots 1000 \
  --cluster-yes

# 平衡所有节点槽位
redis-cli --cluster rebalance 192.168.1.101:7001
```

### 故障节点恢复

```bash
# 节点故障后，重新加入集群
redis-server /etc/redis/redis.conf

# 在其他节点触发故障转移
redis-cli -c -p 7001 cluster failover
```

### 性能监控

```bash
# 查看节点性能
redis-cli -c -p 7001 info stats

# 关键指标：
# instantaneous_ops_per_sec  # 每秒操作数
# used_memory_human          # 内存使用
# connected_clients          # 连接数
```

### 常见错误处理

**MOVED 重定向**
```bash
# 客户端收到 MOVED 错误时，会自动更新槽位映射
# 如果手动连接：
redis-cli -c -p 7001  # 加 -c 参数自动处理重定向
```

**ASK 临时重定向**
```bash
# 槽位迁移时可能出现
# 客户端会自动重试，通常无需处理
```

**CANNOT分配槽位错误**
```bash
# 重新分配槽位
redis-cli --cluster fix 192.168.1.101:7001 \
  --cluster-password yourpassword
```
