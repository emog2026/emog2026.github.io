## 📌 一句话总结

将广域网（WAN）的控制权从运营商手中收回到企业自己手中，用软件智能管理多条网络链路，让企业组网更灵活、更便宜。

---

## 🎯 这是什么？

### 基础定义

SD-WAN（Software-Defined Wide Area Network，软件定义广域网）是将 SDN（软件定义网络）原理应用于广域网的技术。传统企业组网依赖运营商的 MPLS 专线，而 SD-WAN 让企业能够自主管理多条网络链路（MPLS、互联网宽带、4G/5G），智能选择最佳路径传输数据。

### 通俗类比

想象你是一家连锁企业的 IT 负责人，需要连接全国 100 个门店：

**传统方式（MPLS）：**
- 每个门店只能走"高速公路"（MPLS 专线）
- 路线由运营商规划，你说了不算
- 贵！每月每 Mbps 要 $50-$200
- 新门店开张，等运营商装专线要 30-90 天

**SD-WAN 方式：**
- 你可以同时使用"高速公路"（MPLS）、"省道"（互联网宽带）、"乡道"（4G/5G）
- **智能导航**：关键业务（视频会议）走高速公路，大文件（系统更新）走省道
- 省钱！宽带每月 $50-$200 能获得 100Mbps+
- 新门店开张，设备插上网线就能用（零接触部署）

### 为什么存在

**传统 WAN 的痛点：**
1. **成本高昂**：MPLS 专线费用占据企业 IT 预算的大头
2. **部署缓慢**：新站点开通需要等待运营商数月
3. **管理复杂**：每个站点单独配置，无法集中管理
4. **流量模式变化**：云时代 70-80% 流量直达互联网，回传效率低

**SD-WAN 的价值：**
- 降低 30%-60% 的 WAN 成本
- 部署时间从月级降到小时级
- 集中化管理，一个控制器管理所有站点
- 符合云时代的流量模式

## 🏗️ 核心原理

### 它是如何工作的

SD-WAN 通过将**控制平面**（怎么路由）和**数据平面**（实际传输）分离：

```
传统架构：
每个路由器自己决定怎么转发 → 100个站点 = 100个大脑 → 难以协调

SD-WAN架构：
中央控制器制定路由策略 → 所有边缘设备执行 → 1个大脑统一指挥
```

### 关键概念

**1. 边缘设备（Edge/CPE）**
- 专业说：部署在分支机构的数据平面设备
- 通俗说：门店的"智能路由器"，负责执行中央指令

**2. 中央控制器（Controller）**
- 专业说：集中管理平面，负责策略下发和状态监控
- 通俗说：总部的"指挥官"，告诉每个边缘设备怎么走

**3. 编排器（Orchestrator）**
- 专业说：策略管理和业务编排系统
- 通俗说："规则制定者"，定义什么业务走什么路径

**4. 应用感知路由**
- 专业说：基于应用类型和网络质量的动态路径选择
- 通俗说：识别应用类型，智能选择最优路径

### 核心技术机制

**动态路径选择算法：**
```
实时监测指标：
- 延迟（Latency）< 50ms ✓
- 抖动（Jitter）< 10ms ✓
- 丢包率（Loss）< 0.1% ✓
- 可用带宽（Bandwidth）> 10Mbps ✓

决策逻辑：
IF 延迟 < 50ms AND 抖动 < 10ms:
    选择路径A（MPLS）
ELSE:
    选择路径B（互联网）
```

**快速故障切换：**
- BFD（双向转发检测）：毫秒级故障检测
- IPsec 加密：保障传输安全
- 秒级或亚秒级恢复时间

## 💼 应用场景

### 场景 1：多分支机构组网

**痛点**：连锁零售企业全国 200 家门店，总部-门店、门店-门店需要互联，传统 MPLS 专线每月成本 $50,000+。

**方案**：SD-WAN 混合组网，关键业务用 MPLS，普通业务用宽带。

**具体实现：**

```bash
# 站点间 IPsec 隧道配置（Cisco SD-WAN 示例）

# 1. 定义传输接口
interface GigabitEthernet1
  tunnel-interface
   encapsulation ipsec
   color mpls          # MPLS 链路标识
   color biz-internet  # 互联网链路标识
   no allow-service bgp
   allow-service bfd
   allow-service dhcp
   allow-service dns
   allow-service icmp
  no shutdown

# 2. 定义应用感知路由策略
policy
  data-policy APP_ROUTE_POLICY 10
   match
    dns  app-list VIDEO_CONFERENCING
   action
    set-tunnel-tag 10        # 视频会议走 MPLS
   exit
  exit
```

**效果**：成本降低 50%，关键应用性能提升 30%。

### 场景 2：云应用加速

**痛点**：分支机构访问 AWS/Azure/阿里云延迟高，SaaS 应用（Office 365、Salesforce）体验差。

**方案**：SD-WAN 直接优化到云的路径，利用就近接入点。

**具体实现：**

```yaml
# VMware VeloCloud 云加速配置示例

cloudGateways:
  - provider: AWS
    region: us-west-1
    gatewayId: vcg-aws-01
    enable: true

  - appClass: Office365
    action: direct-internet   # 直连互联网
    optimization: true         # 启用加速

  - appClass: Salesforce
    action: use-gateway        # 使用 SD-WAN 网关
    gatewayRegion: nearest     # 选择最近网关

  - name: latency-sensitive
    maxLatency: 50ms
    maxJitter: 10ms
    maxLoss: 0.1%
    preferredPath: mpls        # 延迟敏感业务优先 MPLS
```

**效果**：云应用访问延迟降低 40%，用户体验显著提升。

### 场景 3：分支机构互联网直接访问（DIA）

**痛点**：所有互联网流量回传总部，总部出口带宽不足，用户体验差。

**方案**：分支机构本地互联网出口，减少回传。

**具体实现：**

```bash
# Fortinet Secure SD-WAN 配置示例

# 1. 定义本地互联网 breakout
config system sdwan
    config zone
        set "allow-access" enable
    next

    # 2. 定义应用路由策略
    config service
        edit 1
            set name "Direct_Internet"
            set dst "all"
            set application "YouTube" "Netflix" "General-Internet"
            set mode "standalone"
            set link-group "WAN2"    # 本地互联网链路
            set priority 10
        next

        edit 2
            set name "Business_Apps"
            set dst "10.0.0.0/8"     # 内网流量
            set mode "priority"
            set link-group "MPLS"    # 回传总部
            set priority 1
        next
    end
end

# 3. 安全策略（Secure Web Gateway）
config firewall policy
    edit 1
        set name "DIA_Security"
        set srcaddr "all"
        set dstaddr "all"
        set action "accept"
        set schedule "always"
        set service "ALL"
        set utm-status enable
        set profile-protocol-options "default"
        set av-profile "default"
        set web-filter-profile "default"
    next
end
```

**效果**：总部出口带宽节省 70%，分支机构互联网体验提升。

### 场景 4：混合云专线互联

**痛点**：自建机房与公有云需要稳定连接，传统专线成本高、部署慢。

# 1. 云侧：创建 SD-WAN 云服务（CCN）
# 在阿里云控制台或使用 CLI：

aliyun ccn create-cen \
  --Name "Hybrid-Cloud-SDWAN" \
  --Description "连接总部与阿里云VPC"

# 2. 绑定云企业网实例到 VPC
aliyun ccn attach-cen-child-instance \
  --CenId "cen-xxxx" \
  --ChildInstanceId "vpc-xxxx" \
  --ChildInstanceType "VPC" \
  --ChildInstanceRegionId "cn-hangzhou"

# 3. 侧：配置互联 IP（使用 /30 掩码）
# 互联地址规划示例：
# 云侧 VBR IP: 10.0.0.1/30
# 侧 CPE IP: 10.0.0.2/30
# 可用 IP: 10.0.0.1, 10.0.0.2

# 4. BGP 路由配置
router bgp 65000
 bgp router-id 10.0.0.2

# 5. 主备链路优先级控制（BGP Local Pref）

**效果**：混合云连接稳定，专线故障时自动切换到互联网备份。

### 场景 5：快速灾备和故障切换

**痛点**：主线路故障时，手动切换耗时半小时，业务中断。

**方案**：SD-WAN 毫秒级故障检测，秒级自动切换。

**具体实现：**

```yaml
# Versa Networks SD-WAN 高可用配置

highAvailability:
  enable: true

  # BFD 快速故障检测
  bfd:
    interval: 50ms      # 发送间隔
    multiplier: 3        # 丢失 3 个包即判定故障（150ms 检测时间）

  # 故障切换策略
  failoverPolicy:
    trigger:
      - bfdState: down
      - latencyThreshold: 100ms    # 延迟超过 100ms 触发
      - lossThreshold: 1%           # 丢包超过 1% 触发

    action:
      - switchoverTime: < 1s        # 1 秒内完成切换
      - notify:
          type: email
          recipients: ["netops@example.com"]

  # 路径健康监控
  pathMonitoring:
    - target: 8.8.8.8
      interval: 1s
      timeout: 3s
      method: icmp

    - target: api.crm.com
      interval: 5s
      timeout: 15s
      method: http
      path: /health
```

**效果**：故障切换时间从 30 分钟降到 <1 秒，几乎无感切换。
