> 📚 知识关键词：VPN 部署

---

## 📌 一句话总结

通过加密隧道技术，在公网之上建立安全的私有网络通道，让数据像在专线上一样传输。

---

## 🎯 这是什么？

### 基础定义

VPN（Virtual Private Network，虚拟专用网）是在公共网络上建立加密通道的技术，使数据传输就像在专用线路上一样安全。VPN 隧道封装、加密和认证机制，确保数据的机密性、完整性和真实性。

### 通俗类比

想象你要寄一封机密信件：

**不使用 VPN：**
- 信封是透明的
- 邮递员可以看到内容
- 路途中任何人都能拆开信封

**使用 VPN：**
- 把信件装进加密保险箱
- 只有收发双方有钥匙
- 即使保险箱被截获，没有钥匙也打不开

### 为什么存在

**核心需求：**
1. **远程办公**：员工在家/出差时安全访问公司内网
2. **数据加密**：在咖啡厅、机场等公共 Wi-Fi 上保护隐私
3. **跨地域组网**：连接多个办公室的私有网络
4. **访问控制**：绕过地理位置限制（合规前提下）
5. **成本优化**：用互联网替代昂贵的专线

## 🏗️ 核心原理

### 它是如何工作的

**VPN 隧道建立过程：**

```
1. 握手阶段（建立隧道）
   客户端                    服务器
      |                          |
      |--- 1. 连接请求 --------->|
      |                          |
      |<-- 2. 证书/密钥交换 -----|
      |                          |
      |--- 3. 验证完成 --------->|
      |                          | ✓ 隧道建立

2. 数据传输（加密通信）
   客户端                    互联网                    服务器
      |                          |                          |
      |---[明文数据]              |                          |
      |                          |                          |
      |[加密/封装]---[密文数据]---------------------------->[解密/解封装]
      |                          |                          |
      |                          |                    [明文数据]
```

### 关键概念

**1. 隧道（Tunnel）**
- 专业说：封装原始数据包的传输通道
- 通俗说：加密的"快递管道"，外面看不到里面装的是什么

**2. 加密（Encryption）**
- 专业说：使用对称/非对称加密算法保护数据机密性
- 通俗说：只有收发双方能懂的"加密语言"

**3. 认证（Authentication）**
- 专业说：验证通信双方身份的机制
- 通俗说：确认对方真的是你要联系的人

**4. 封装（Encapsulation）**
- 专业说：将原始数据包装入新的数据包格式
- 通俗说：给信件套上多层信封，每层有不同的标签

### 核心技术机制

**数据封装流程：**
```
原始数据包：
[IP头][TCP头][应用数据]

VPN 封装后：
[新IP头][VPN头][加密的: IP头][TCP头][应用数据]
    ↑         ↑
  公网路由   VPN元数据
```

**加密开销：**
- 所有数据需要加密/解密计算
- 数据包增加 VPN 头部（通常 20-60 字节）
- MTU（最大传输单元）需要调整以避免分片

## 📜 VPN 协议对比

### 主流协议对比表

| 协议 | 代码量 | 加密算法 | 速度 | 安全性 | 平台支持 | 适用场景 |
|------|--------|----------|------|--------|----------|----------|
| **WireGuard** | ~4,000 行 | ChaCha20/Poly1305 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 全平台 | 现代部署、高性能需求 |
| **OpenVPN** | ~100,000 行 | AES-256-GCM | ⭐⭐⭐☆☆ | ⭐⭐⭐⭐☆ | 全平台 | 兼容性需求、传统场景 |
| **IPsec/IKEv2** | 中等 | AES-CBC/GCM | ⭐⭐⭐⭐☆ | ⭐⭐⭐⭐⭐ | 原生支持 | 站点到站点、企业级 |
| **L2TP/IPsec** | 较复杂 | AES-256 | ⭐⭐☆☆☆ | ⭐⭐⭐☆☆ | 广泛 | 传统 Windows 客户端 |
| **SSTP** | 专有 | AES-256 | ⭐⭐⭐☆☆ | ⭐⭐⭐⭐☆ | Windows | Windows 环境优先 |

### WireGuard：现代 VPN 之选

**优势：**
- **极简代码**：仅 4,000 行代码（OpenVPN 100,000+ 行），攻击面小，易于审计
- **现代加密栈**：使用 Noise Protocol Framework
  - ChaCha20 加密
  - Poly1305 认证
  - BLAKE2s 哈希
  - Curve25519 密钥交换
- **无缝漫游**：网络切换时连接不断（Wi-Fi ↔ 4G）
- **内核集成**：Linux 内核原生支持，性能最优

**适用场景：**
- 个人 VPN 服务器
- 高性能企业网关
- 容器/K8s 网络策略

### OpenVPN：成熟可靠

**优势：**
- 十五年以上生产验证
- 灵活的配置选项
- 强大的社区支持
- 跨平台客户端完善

**适用场景：**
- 需要高度自定义的企业部署
- 复杂的认证集成（LDAP、RADIUS）
- 传统运维环境

## 💼 应用场景

### 场景 1：个人隐私保护

**痛点**：在咖啡厅使用公共 Wi-Fi，担心账号密码被窃取。

**方案**：搭建个人 VPN 服务器，所有流量走加密隧道。

**具体实现：**

```bash
# ========== WireGuard 服务器端配置 ==========
# 安装 WireGuard（Ubuntu/Debian）
sudo apt update
sudo apt install wireguard

# 生成密钥对
wg genkey | tee privatekey | wg pubkey > publickey

# 创建配置文件
sudo nano /etc/wireguard/wg0.conf

# ===== 配置内容 =====
[Interface]
PrivateKey = <服务器私钥>
Address = 10.0.0.1/24              # VPN 内网 IP
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; \
         iptables -A FORWARD -o wg0 -j ACCEPT; \
         iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; \
           iptables -D FORWARD -o wg0 -j ACCEPT; \
           iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE
ListenPort = 51820

[Peer]
PublicKey = <客户端公钥>
AllowedIPs = 10.0.0.2/32           # 允许的客户端 IP
# ===== 配置结束 =====

# 启动 WireGuard
sudo wg-quick up wg0
sudo systemctl enable wg-quick@wg0
```

```bash
# ========== WireGuard 客户端配置（Linux/Mac）==========
sudo nano /etc/wireguard/wg0-client.conf

# ===== 配置内容 =====
[Interface]
PrivateKey = <客户端私钥>
Address = 10.0.0.2/24
DNS = 8.8.8.8, 8.8.4.4

[Peer]
PublicKey = <服务器公钥>
Endpoint = <服务器公网IP>:51820
AllowedIPs = 0.0.0.0/0             # 全局流量走 VPN
PersistentKeepalive = 25
# ===== 配置结束 =====

# 连接
sudo wg-quick up wg0-client
```

**效果**：公共 Wi-Fi 上所有数据加密，防止中间人攻击。

### 场景 2：远程办公访问公司内网

**痛点**：员工在家需要访问公司内网 OA、文件服务器、开发环境。

**方案**：OpenVPN + LDAP 认证，集中管理用户权限。

**具体实现：**

```bash
# ========== OpenVPN 服务器端配置 ==========

# 1. 安装 OpenVPN 和 Easy-RSA（证书管理）
sudo apt install openvpn easy-rsa

# 2. 初始化 PKI（公钥基础设施）
make-cadir ~/openvpn-ca
cd ~/openvpn-ca
source vars
./clean-all
./build-ca  # 生成 CA 证书

# 3. 生成服务器证书和密钥
./build-key-server server

# 4. 生成 Diffie-Hellman 参数（密钥交换）
./build-dh

# 5. 生成 HMAC 签名（防止 DDoS）
openvpn --genkey --secret ta.key

# 6. 创建服务器配置文件
sudo nano /etc/openvpn/server.conf

# ===== 配置内容 =====
port 1194
proto udp
dev tun
ca ca.crt
cert server.crt
key server.key
dh dh2048.pem
tls-auth ta.key 0
cipher AES-256-CBC
auth SHA256
server 10.8.0.0 255.255.255.0      # VPN 客户端 IP 池
push "redirect-gateway def1"       # 全局流量走 VPN
push "dhcp-option DNS 8.8.8.8"
keepalive 10 120
comp-lzo no
persist-key
persist-tun
status openvpn-status.log
verb 3
plugin /usr/lib/openvpn/radiusplugin.so /etc/openvpn/radiusplugin.cnf
# ===== 配置结束 =====

# 7. 启动 OpenVPN
sudo systemctl start openvpn@server
sudo systemctl enable openvpn@server

# 8. 配置防火墙
sudo ufw allow 1194/udp
sudo ufw allow OpenSSH
```

```bash
# ========== OpenVPN 客户端配置 ==========

# 生成客户端证书
./build-key client1

# 客户端配置文件（client.ovpn）
client
dev tun
proto udp
remote <服务器公网IP> 1194
resolv-retry infinite
nobind
user nobody
group nogroup
persist-key
persist-tun
ca ca.crt
cert client1.crt
key client1.key
remote-cert-tls server
cipher AES-256-CBC
auth SHA256
verb 3
key-direction 1
tls-auth ta.key 1
```

**效果**：员工安全访问内网资源，审计追踪用户行为。

### 场景 3：站点到站点组网

**痛点**：公司总部和分部需要内网互通，传统专线太贵。

**方案**：IPsec VPN 隧道连接两个网络。

**具体实现：**

```bash
# ========== 总部端配置（strongSwan IPsec）==========

# 1. 安装 strongSwan
sudo apt install strongswan-starter strongswan-pki

# 2. 生成证书
ipsec pki --gen --type rsa --size 4096 --outform pem > serverKey.pem
ipsec pki --self --ca --in serverKey.pem \
    --dn "C=CN, O=Company, CN=HQ-VPN" \
    --san "DNS=hq.vpn.example.com" \
    --flag ikeIntermediate --lifetime 3650 \
    --outform pem > serverCert.pem

# 3. IPsec 配置
sudo nano /etc/ipsec.conf

# ===== 配置内容 =====
config setup
    charondebug="ike 1, knl 1, cfg 0"
    uniqueids=no

conn hq-to-branch
    keyexchange=ikev2
    ike=aes256gcm16-sha256-modp3072!
    esp=aes256gcm16-sha256!
    leftid=@hq.vpn.example.com
    left=203.0.113.10              # 总部公网 IP
    leftsubnet=10.0.0.0/24        # 总部内网
    leftcert=hqCert.pem
    leftfirewall=yes
    rightid=@branch.vpn.example.com
    right=198.51.100.20           # 分部公网 IP
    rightsubnet=10.1.0.0/24        # 分部内网
    right=%any
    auto=add
    mobike=no
# ===== 配置结束 =====

# 4. IPsec 密钥配置
sudo nano /etc/ipsec.secrets

# ===== 配置内容 =====
: RSA serverKey.pem
# ===== 配置结束 =====

# 5. 启动 IPsec
sudo ipsec restart
sudo ipsec up hq-to-branch
```

```bash
# ========== 分部端配置 ==========

# 配置结构与总部类似，但 left/right 对调

conn branch-to-hq
    keyexchange=ikev2
    ike=aes256gcm16-sha256-modp3072!
    esp=aes256gcm16-sha256!
    leftid=@branch.vpn.example.com
    left=198.51.100.20
    leftsubnet=10.1.0.0/24
    leftcert=branchCert.pem
    leftfirewall=yes
    rightid=@hq.vpn.example.com
    right=203.0.113.10
    rightsubnet=10.0.0.0/24
    right=%any
    auto=add
    mobike=no
```

**效果**：总部和分部内网互通，文件共享、统一管理。

### 场景 4：Docker 容器网络加密

**痛点**：多台 Docker 主机之间的容器通信需要加密。

**方案**：WireGuard + Docker 网络，跨主机容器加密通信。

**具体实现：**

```yaml
# docker-compose.yml
version: '3.8'

services:
  # WireGuard VPN 容器
  wg0:
    image: linuxserver/wireguard
    container_name: wireguard
    hostname: wg0
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Shanghai
      - SERVERPORT=51820
      - PEERS=2,peer1,peer2
      - PEERDNS=auto
    volumes:
      - ./wg-config:/config
    ports:
      - 51820:51820/udp
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    restart: unless-stopped

  # 应用容器（通过 VPN 网络）
  app:
    image: nginx:alpine
    container_name: webapp
    network_mode: service:wg0    # 共享 WireGuard 网络命名空间
    depends_on:
      - wg0
```

```bash
# WireGuard 配置文件
# wg-config/config/wg0.conf

[Interface]
PrivateKey = <私钥>
Address = 10.10.0.1/24
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; \
         iptables -A FORWARD -o wg0 -j ACCEPT; \
         iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

[Peer]
PublicKey = <对端公钥>
AllowedIPs = 10.10.0.0/24
Endpoint = <对端公网IP>:51820
PersistentKeepalive = 25
```

**效果**：跨主机容器通信加密，无需修改应用代码。

## ⚖️ 优缺点分析

| 维度 | ✅ 优点 | ❌ 缺点/局限性 |
|------|---------|---------------|
| **安全性** | 强加密、身份认证 | 配置错误可导致泄露 |
| **成本** | 使用互联网，成本低 | 高性能需要硬件加速 |
| **灵活性** | 支持多种协议、场景 | 协议选择复杂 |
| **性能** | WireGuard 接近原生 | 加密带来计算开销 |
| **可靠性** | 多路径、自动重连 | 依赖公网质量 |
| **合规性** | 符合安全审计要求 | 需要配合其他安全措施 |
| **管理** | 集中认证、审计 | 大规模部署需管理系统 |

### 性能开销

**加密开销对比：**
- WireGuard：~5-10% CPU 开销（内核优化）
- OpenVPN：~15-25% CPU 开销（用户空间）
- IPsec：~10-20% CPU 开销（内核/硬件混合）

**带宽影响：**
- 数据包增加 20-60 字节头部
- MTU 需要调整为 1280 或 1400（避免分片）

## ⚠️ 注意事项

### 安全风险

1. **配置错误**：DNS 泄露、IP 泄露、日志记录
2. **密钥管理**：私钥泄露、证书过期
3. **拒绝服务**：VPN 服务本身可能成为攻击目标
4. **合规性**：某些地区对 VPN 使用有法律限制

### 实施建议

1. **从小规模开始**：先测试，再全面部署
2. **备份配置**：证书、密钥要备份
3. **监控日志**：及时发现异常
4. **定期更新**：软件和系统补丁
5. **应急预案**：VPN 故障时的备用方案

### 加密强度

# ChaCha20-Poly1305（移动设备友好）

### 证书管理

```bash
# 使用 Easy-RSA 生成和管理证书
./pki init
./pki build-ca
./pki build-server-full server-name
./pki build-client-full client-name

# 定期轮换密钥（建议 1-2 年）
```

### 防火墙规则

```bash
# 最小端口暴露
ufw allow 1194/udp      # OpenVPN
ufw allow 51820/udp    # WireGuard

# 限制来源 IP（如果固定）
ufw allow from 203.0.113.0/24 to any port 1194 proto udp
```
