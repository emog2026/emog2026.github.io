## 🎯 它是做什么的？

**FunASR** 是阿里巴巴 ModelScope 团队开源的**工业级语音识别工具包**，专为企业级应用设计。

想象一下：
- 你需要给 100 小时的录音转文字，传统工具要等 100 小时
- 你想识别谁在说话（说话人分离），但要额外花钱买服务
- 你需要实时语音识别，但开源工具太慢
- 你想在边缘设备（树莓派、嵌入式）上运行语音识别

**FunASR 解决这些问题：**
- 🚀 **极致速度**：340 倍实时（vLLM），比 Whisper 快 26 倍
- 🌍 **50+ 语言**：Qwen3-ASR 支持 52 语言，Nano 支持 31 语言
- 👥 **说话人分离**：内置 cam++ 模型，一次调用自动识别
- 😊 **情感识别**：SenseVoice 内置情绪检测
- 📡 **流式识别**：WebSocket 实时输出，边说边转
- 💻 **CPU 友好**：SenseVoice 在 CPU 上 17 倍实时
- 🦖 **边缘部署**：llama.cpp / GGUF 二进制，无需 Python
- 🔓 **完全开源**：MIT 许可，可商用

**核心特点：工具包而非单一模型**
FunASR 不是"一个模型"，而是**完整工具箱**——你可以根据场景选择：
- **Fun-ASR-Nano**（旗舰 LLM-ASR，GPU，340 倍实时）
- **SenseVoice**（CPU 友好，+ 情感 & 音频事件）
- **Paraformer**（低延迟流式）

## 🔑 核心概念解读

**340x Realtime（340 倍实时）**
- **专业说**：处理 1 小时音频仅需约 1.8 秒（3600 秒 / 340 ≈ 10.6 秒）
- **通俗说**：你还在喝口水的功夫，AI 已经把整个录音转完了

**Speaker Diarization（说话人分离）**
- **专业说**：自动识别音频中的不同说话人并打标签
- **通俗说**：像给会议做记录，自动标注"张三说"、"李四说"

**VAD（Voice Activity Detection，语音活动检测）**
- **专业说**：自动检测音频中的有效语音片段，过滤静音
- **通俗说**：像有人帮你按暂停键，只保留说话的部分

**Streaming（流式识别）**
- **专业说**：边接收音频边输出文字，无需等待完整音频
- **通俗说**：像实时字幕，边听边打字，不等说话结束

**GGUF / llama.cpp Runtime**
- **专业说**：量化模型格式，可在 CPU/边缘设备以单文件运行
- **通俗说**：把大模型"压缩"成一个小文件，树莓派也能跑

## 💡 切实可落地的例子（3个场景）

### **场景 1：个人开发者——快速处理录音**
- **痛点**：播客/会议录音很长，手动转文字太慢
- **解决方案**：用 FunASR 一行命令搞定
- **具体实现步骤**：
  ```bash
  # 1. 安装
  pip install torch torchaudio
  pip install funasr

  # 2. Python 代码（旗舰模型，GPU）
  python
  from funasr import AutoModel

  model = AutoModel(model="FunAudioLLM/Fun-ASR-Nano-2512", device="cuda")
  result = model.generate(input="podcast.wav")
  print(result[0]["text"])
  # 1 小时音频约 10 秒完成
  ```

  ```bash
  # 或者用 CLI（更简单）
  funasr podcast.wav --output-format txt --output-dir ./output
  ```
- **效果**：1 小时录音 10 秒转完，准确率 95%+

### **场景 2：企业会议记录——说话人分离**
- **痛点**：会议录音需要知道谁说了什么，人工整理太累
- **解决方案**：用 SenseVoice 一次性完成识别 + 说话人标签
- **具体实现步骤**：
  ```bash
  # 1. 启动 OpenAI 兼容 API 服务
  pip install funasr vllm fastapi uvicorn
  funasr-server --device cuda
  # → 服务运行在 localhost:8000

  # 2. 调用 API（带说话人分离和时间戳）
  curl http://localhost:8000/v1/audio/transcriptions \
    -F file=@meeting.wav \
    -F model=sensevoice \
    -F response_format=verbose_json \
    -F speaker_diarization=true

  # 输出示例：
  # {
  #   "text": "完整文字",
  #   "segments": [
  #     {"start": 0.6, "end": 5.2, "speaker": "spk0", "text": "大家好..."},
  #     {"start": 5.3, "end": 10.1, "speaker": "spk1", "text": "今天我们要..."}
  #   ]
  # }
  ```
- **效果**：自动生成带说话人标签的会议记录，格式可直接导入笔记软件

### **场景 3：边缘设备部署——树莓派语音助手**
- **痛点**：想用树莓派做语音助手，但没 GPU，传统模型太慢
- **解决方案**：用 GGUF 二进制版本，CPU 也能 17 倍实时
- **具体实现步骤**：
  ```bash
  # 1. 下载预编译二进制（Linux/macOS/Windows）
  # 从 https://github.com/modelscope/FunASR/releases

  # 2. 下载模型
  bash download-funasr-model.sh sensevoice ./gguf

  # 3. 运行（无需 Python，单文件）
  llama-funasr-sensevoice \
    -m ./gguf/SenseVoiceSmall-f16.gguf \
    --vad ./gguf/fsmn-vad.gguf \
    -a test.wav

  # → 输出：欢迎大家来体验达摩院推出的语音识别模型
  ```
- **效果**：树莓派 4 上也能实时运行，准确率比 whisper.cpp 高 3 倍

## 🚀 部署方式

### 1️⃣ **OpenAI 兼容 API（推荐）**
```bash
pip install funasr vllm fastapi uvicorn
funasr-server --device cuda
# → localhost:8000 提供与 OpenAI 兼容的 API
```

### 2️⃣ **Python API**
```python
from funasr import AutoModel
model = AutoModel(model="paraformer-zh", vad_model="fsmn-vad", device="cuda")
result = model.generate(input="audio.wav")
```

### 3️⃣ **命令行（CLI）**
```bash
funasr audio.wav --output-format srt --spk --timestamps
```

### 4️⃣ **llama.cpp / GGUF（边缘部署）**
```bash
llama-funasr-sensevoice -m ./gguf/SenseVoiceSmall-f16.gguf -a audio.wav
```

### 5️⃣ **Docker 流式服务**
```bash
docker pull registry.cn-hangzhou.aliyuncs.com/funasr_repo/funasr:funasr-runtime-sdk-online-cpu-0.1.12
```
