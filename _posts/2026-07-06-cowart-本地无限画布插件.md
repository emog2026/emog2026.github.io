📌 **一句话总结**：给 Codex 装一块可视化无限画布的本地插件，能在上面构思、标注、生成和迭代图片

---

🎯 **它是做什么的？**

Cowart 是一个**面向 Codex（OpenAI 编程 Agent）的本地无限画布插件**。它给 AI 编程助手"长出一块白板"，让 AI 不再只能写代码、处理文字，还能**在画布上看图、画标注、生成图片、根据标注改图**。

它基于开源的 **tldraw**（流行的网页无限画布工具），画布跑在本地网页服务里。一个关键设计：**画布数据不存进插件仓库，而是存到当前项目的 `canvas/` 目录**，跟着项目走、可纳入版本控制、团队可共享。

**解决的痛点**：
- 传统 AI 编程助手（Codex/Claude）只能处理文字和代码，**看不见也画不了图**——想让它"看着这张图改一改""在这里生成个图标"根本做不到。
- 用 Midjourney/DALL·E 单独生图，又要手动下载、改尺寸、塞回项目，流程割裂。
- 想在图上标几笔（"这里加个按钮""这块颜色不对"）再让 AI 照着改，没有顺手的闭环工具。

Cowart 把"画布 + AI 生图 + 标注迭代"打通成一个流程，且全部数据本地化、归属当前项目。

**和同类产品的区别**：
- 对比 **tldraw / Excalidraw / Miro**（纯画布工具）：那些只是白板，没有 AI；Cowart 让 AI 能读懂画布内容并直接在上面生图、改图。
- 对比 **Midjourney / DALL·E / GPT-Image**（纯生图工具）：那些只能出图，没有画布和标注迭代；Cowart 提供"画框→生图→标注→修订"的完整链路。
- 对比 **Figma + AI 插件**：Cowart 是命令行/Codex 原生工作流，数据落本地项目目录，更适合开发者而非设计师。

---

🔑 **核心概念解读**

**Codex 插件（Plugin）**
- 专业说：扩展 Codex Agent 能力的本地模块，通过 skill + MCP 工具接入
- 通俗说：给 Codex 装的"外挂功能包"，装上后它就多了"画布"这项能力。
- 生活类比：就像给微信装一个小程序——本体不变，多了一个新功能入口。

**无限画布（Infinite Canvas / tldraw）**
- 专业说：可无限平移缩放的矢量画布，支持手绘、形状、文字、图片自由排版
- 通俗说：一块永远画不满、能随便拖动缩放的"数字大白板"。
- 生活类比：像 Miro、Figma 或 iPad 的 Freeform，随便你往上贴东西、画箭头。

**AI image holder（AI 图片占位框）**
- 专业说：画布上带尺寸比例约束的图片占位容器，供 Codex 读取并填入生成图
- 通俗说：先在画布上画一个"空相框"，告诉 AI"在这里给我生成一张图"，它就按相框尺寸出图填进去。
- 生活类比：先在墙上钉个空画框，再让画家按框的大小画一幅画挂上去。

**标注迭代（Annotation-based edit）**
- 专业说：读取用户在截图上的标注（箭头、圈注），生成去除标注痕迹的干净修订图
- 通俗说：你在图上画几笔圈出"这里要改"，AI 看懂后给你一张改好的干净新图，原图和标注都不动。
- 生活类比：像在打印稿上拿红笔批改，助手照着批注给你出一版新的干净稿。

**MCP 工具（Model Context Protocol）**
- 专业说：让 AI 读取画布选择状态、插入图片、保存资源的标准接口协议
- 通俗说：AI 和画布之间"对话用的电话"，AI 靠它知道你选了啥、能把图塞进画布。

💡 **切实可落地的例子**

**场景 1：独立开发者 / 做 Demo 网站配图**
- 痛点：用 Codex 写代码搭网站，但 hero 区需要一张配图，平时得切到 Midjourney 生成、下载、调尺寸再塞进项目，很割裂。
- 方案：用 Cowart 画布，在 Codex 里直接"画框→生图→落进项目"。
- 具体步骤：
  ```bash
  # 1. 让 Codex 自动安装插件（把这段话发给 Codex）：
  请从 https://github.com/zhongerxin/cowart.git 安装 Cowart Codex 插件。
  clone 到 ~/plugins/cowart，确认 .codex-plugin/plugin.json 存在，
  加入 personal marketplace，运行 codex plugin marketplace add ~，
  再运行 codex plugin add cowart@personal。
  ```
  ```text
  # 2. 在 Codex 中打开画布：
  Open the Cowart canvas for this project.

  # 3. 在画布上画一个 AI image holder（空相框）并选中它，然后说：
  Generate a new image into the selected Cowart AI image holder.
  ```
- 效果：Codex 按相框比例生成图片并自动插入，图片资源保存到项目 `canvas/pages/<page-id>/assets/`，跟着项目走、可提交到 git。再也不用在多个工具间来回切换。

**场景 2：UI/产品设计迭代（标注驱动改图）**
- 痛点：让 AI 改一张设计图，光用文字描述"左上角那个按钮往右挪一点、颜色换成蓝色"很容易表达不清，AI 改出来也不对。
- 方案：在图上直接画标注，让 AI 看图改图。
- 具体步骤：
  ```text
  # 1. 在 Cowart 画布中对要改的图片做标注（画箭头、圈出区域、写批注）
  # 2. 把带标注的画面截图，发给 Codex
  # 3. 对 Codex 说：
  Use my Cowart annotation screenshot to generate a clean revised image beside the original.
  ```
  ```bash
  # 修订图会放在原图旁边，原图和标注保持不动，方便对比
  # 数据落盘位置：
  # canvas/pages/<page-id>/cowart-canvas.json   ← 画布结构
  # canvas/pages/<page-id>/assets/              ← 图片资源
  ```
- 效果：AI 读懂你画的箭头和圈注，生成一张去掉标注痕迹的干净修订图，放在原图旁边。直观、可追溯，比纯文字描述准确得多。

**场景 3：内容创作 / 批量素材构思**
- 痛点：写公众号、做 PPT 需要一组风格统一的配图，脑子里有大致想法但要在文字描述和成品之间反复试错。
- 方案：把无限画布当"灵感板"，多放几个占位框，一次性生成多张图、自由排版对比。
- 具体步骤：
  ```bash
  # 自定义本地服务（按需调整）：
  COWART_PORT=43217                      # 本地服务端口，默认 43217
  COWART_PROJECT_DIR=/path/to/project    # 画布数据所属的项目目录
  COWART_CANVAS_DIR=$COWART_PROJECT_DIR/canvas  # 画布数据目录

  # 也可直接启动画布服务并指定项目目录：
  ./scripts/start-canvas.sh /path/to/user/project
  ```
  ```text
  # 在画布上摆多个 holder，分别选中并描述：
  Generate a hero illustration in the selected holder, flat design, blue palette.
  # 再选另一个 holder：
  Generate a matching icon set into this holder, same style.
  ```
- 效果：一块画布上同时铺开多张候选图，自由拖拽、缩放、对比挑版。画布本身（含所有图片）随项目持久化，下次打开还在，团队拉代码就能看到完整构思过程。

👥 **适合谁用？**

✅ 用 **Codex** 做开发、需要在项目里**生成或迭代图片**的开发者
✅ 做 **Demo 网站、独立产品**，需要快速出配图/UI 素材的人
✅ **UI/产品设计**想用"标注驱动"方式让 AI 精准改图的人
✅ 喜欢**白板式构思**、需要可视化整理灵感和素材的内容创作者
✅ 看重**数据本地化**、希望画布资产纳入项目版本控制的团队

❌ 只用**普通 ChatGPT 网页版**、不用 Codex 的用户（这是 Codex 专属插件）
❌ 需要**专业矢量设计/排版**的设计师（tldraw 画布精度不如 Figma/Illustrator）
❌ 想要**云端协作**实时多人同画的团队（Cowart 是本地单机画布，非云协作）
❌ 只需**偶尔生一两张图**的轻度用户（杀鸡用牛刀，直接用 ChatGPT/Midjourney 更省事）

⚠️ **注意事项**

- **付费/免费**：开源免费（仓库 public，基于开源 tldraw，致谢 tldraw 项目）
- **运行环境**：必须是 **Codex** 环境（需通过 `codex plugin` 命令体系安装）；安装后建议**新开一个 Codex 对话**让 skill 和 MCP 工具完整加载
- **数据归属**：画布数据默认存到**当前项目**的 `canvas/` 目录（而非插件仓库），意味着会进入项目 git——注意不要把不该提交的图片素材误提交
- **本地服务**：画布跑在本地网页服务，默认端口 `43217`（可用 `COWART_PORT` 改），非云端
- **学习曲线**：⭐⭐⭐☆☆（中难度）—— 装好插件后操作简单（画框→说话→出图），但需要熟悉 Codex 插件体系、MCP 工具、以及"holder 选择状态"等概念
- **生图能力依赖**：Cowart 本身是画布+编排层，**实际生图质量取决于 Codex 背后接入的图像模型**（如 GPT-Image），插件不自带模型
- **替代方案**：
  - **tldraw / Excalidraw + 手动生图**：纯画布，自己切工具出图再贴回
  - **Figma + AI 插件**（如 Magician、Diagram）：设计师向，云端协作
  - **Miro / FigJam**：团队白板协作，AI 能力较弱
  - **直接用 ChatGPT/Claude 的图像功能**：无需画布，但缺少可视化编排和标注迭代闭环
