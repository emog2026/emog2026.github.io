## 📌 一句话总结
Kubernetes 的应用商店，像手机应用商店一样一键安装复杂应用。

---

## 🎯 这是什么？

### 基础定义
Helm 是 Kubernetes 的包管理器，类似于 Linux 的 `apt`、`yum`，或者 Node.js 的 `npm`，但用于 Kubernetes 应用。它帮助您定义、安装和升级复杂的 Kubernetes 应用。

### 通俗类比

**想象手机应用商店**：

- **Kubernetes** = 手机操作系统
- **Helm** = 应用商店（App Store / Google Play）
- **Chart（Helm 包）** = 应用程序（如微信、支付宝）
- **Release（发布版）** = 已安装的应用实例
- **Repository（仓库）** = 应用商店服务器

没有 Helm，部署 Kubernetes 应用就像：
- 手动下载源码 → 配置依赖 → 编译 → 安装
- 每个细节都要自己配置，容易出错

有了 Helm：
- `helm install` → 一键安装完整应用
- 像 `npm install` 一样简单

**另一个类比**：
- **传统方式**：像组装家具，买来零件自己拼（需要专业知识）
- **Helm 方式**：像宜家家具，开箱即用，按说明书简单组装

### 为什么存在

当您在 Kubernetes 上部署应用时，会遇到的问题：

- 🚨 **应用太复杂**：一个应用需要 Deployment、Service、ConfigMap、Secret、Ingress 等
- 📦 **依赖管理难**：多个组件有依赖关系，手动管理容易出错
- 🔄 **升级困难**：更新应用需要修改多个 YAML 文件
- 🎛️ **配置管理**：不同环境需要不同配置
- 📊 **版本管理**：无法追踪应用版本和历史

### 关键概念

#### 1. Chart（Helm 包）

**专业说**：Helm 包，包含一组 Kubernetes 资源定义的集合

**通俗说**：像"软件安装包"，里面包含应用所需的所有组件

**Chart 结构**：
```
myapp/
├── Chart.yaml          # Chart 信息（名称、版本、描述）
├── values.yaml         # 默认配置值
├── values.schema.json  # 配置验证模式
├── templates/          # Kubernetes 模板文件
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   ├── configmap.yaml
│   └── _helpers.tpl    # 可重用的模板片段
├── charts/            # 依赖的 Chart
├── .helmignore        # 打包时忽略的文件
└── README.md          # 使用说明
```

**Chart.yaml 示例**：
```yaml
apiVersion: v2
name: myapp
description: A Helm chart for Kubernetes
type: application
version: 0.1.0         # Chart 版本
appVersion: "1.0.0"    # 应用版本
kubeVersion: ">=1.19.0-0"
keywords:
  - web
  - application
maintainers:
  - name: John Doe
    email: john@example.com
```

#### 2. Release（发布版）

**专业说**：Chart 的一个运行实例

**通俗说**：像"已安装的应用"，一个 Chart 可以安装多次，每次都是一个 Release

**特点**：
- 同一个 Chart 可以有多个 Release
- 每个 Release 有独立的名称和配置
- 支持版本历史和回滚

**示例**：
```bash
# 安装同一个 Chart 的多个实例
helm install myapp-prod ./myapp --values prod-values.yaml
helm install myapp-staging ./myapp --values staging-values.yaml
helm install myapp-dev ./myapp --values dev-values.yaml
```

#### 3. Repository（仓库）

**专业说**：存储和分发 Chart 的服务器

**通俗说**：像"应用商店"，存放各种应用包

**类型**：
- **官方仓库**：https://helm.sh/charts
- **私有仓库**：自己搭建的仓库（ChartMuseum、Harbor、OCI）
- **第三方仓库**：社区维护的仓库

**常用仓库**：
```bash
# 添加官方仓库
helm repo add stable https://charts.helm.sh/stable

# 添加 Bitnami 仓库
helm repo add bitnami https://charts.bitnami.com/bitnami

# 添加 Emissary 仓库
helm repo add emissary https://emissary-ingress.emissary.io/charts

# 更新仓库索引
helm repo update

# 查看所有仓库
helm repo list

# 搜索 Chart
helm search repo nginx
```

#### 4. Values（配置值）

**专业说**：覆盖 Chart 模板中的默认配置

**通俗说**：像"安装配置选项"，定制化应用

**values.yaml 示例**：
```yaml
# 默认配置
replicaCount: 1

image:
  repository: nginx
  pullPolicy: IfNotPresent
  tag: "1.25"

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: false
  className: "nginx"
  annotations: {}
    cert-manager.io/cluster-issuer: "letsencrypt-prod"

resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 250m
    memory: 256Mi

autoscaling:
  enabled: false
  minReplicas: 1
  maxReplicas: 100
  targetCPUUtilizationPercentage: 80
```

**覆盖配置**：
```bash
# 使用文件覆盖
helm install myapp ./myapp --values prod-values.yaml

# 使用命令行覆盖
helm install myapp ./myapp --set replicaCount=3

# 多个值覆盖
helm install myapp ./myapp \
  --set image.tag=1.26 \
  --set resources.requests.cpu=500m \
  --set ingress.enabled=true

# 使用嵌套值
helm install myapp ./myapp --set service.port=8080

# 使用列表
helm install myapp ./myapp --set env[0].name=DATABASE_HOST,env[0].value=localhost
```

#### 5. Template（模板）

**专业说**：使用 Go 模板语法的 Kubernetes YAML 文件

**通俗说**：像"配置模板"，根据 Values 生成最终的 YAML

**模板语法**：
```yaml
# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "myapp.name" . }}-deployment
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      {{- include "myapp.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "myapp.selectorLabels" . | nindent 8 }}
    spec:
      containers:
      - name: {{ .Chart.Name }}
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
        imagePullPolicy: {{ .Values.image.pullPolicy }}
        ports:
        - name: http
          containerPort: {{ .Values.service.port }}
          protocol: TCP
        livenessProbe:
          httpGet:
            path: /
            port: http
        readinessProbe:
          httpGet:
            path: /
            port: http
        resources:
          {{- toYaml .Values.resources | nindent 10 }}
```

**模板函数**：
```yaml
# 字符串函数
{{ .Values.image.tag | upper }}
{{ .Values.image.tag | quote }}
{{ .Values.image.tag | default "latest" }}

# 数值函数
{{ .Values.replicaCount | int }}
{{ .Values.replicaCount | float64 }}

# 列表函数
{{ range .Values.env }}
- name: {{ .name }}
  value: {{ .value }}
{{ end }}

# 条件判断
{{ if .Values.ingress.enabled -}}
...ingress 配置...
{{ end }}

{{ if eq .Values.environment "production" }}
- name: PRODUCTION
  value: "true"
{{ end }}

# 命名模板
{{ define "myapp.labels" -}}
helm.sh/chart: {{ .Chart.Name }}-{{ .Chart.Version }}
{{ include "myapp.selectorLabels" . }}
{{ if .Chart.AppVersion }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
{{ end }}
{{- end }}
```

## 📜 发展背景

### 起源
- **2015年**：Deis 公司（后被 Microsoft 收购）创建 Helm
- **动机**：简化 Kubernetes 应用的部署和管理
- **名称来源**：舵手（掌舵人），寓意控制方向

### 演进历程

| 年份 | 版本 | 里程碑 |
|------|------|--------|
| 2015 | Helm 1 | 首个公开版本 |
| 2016 | Helm 2 | 引入 Tiller（服务端组件） |
| 2017 | CNCF 接管 | 成为 CNCF 孵化项目 |
| 2018 | Helm 2.10 | 支持 Python、Java 客户端 |
| 2019 | Helm 3 | 移除 Tiller，纯客户端架构 |
| 2020 | Helm 3.2 | 支持 OCI 注册表 |
| 2021 | Helm 3.5 | 库支持（可共享 Chart 片段） |
| 2022 | Helm 3.10 | OCI 认证支持 |
| 2023 | Helm 3.12 | 证书验证、依赖管理增强 |
| 2024 | Helm 3.15+ | 持续改进稳定性和性能 |

### 当前状态
- **地位**：Kubernetes 包管理的事实标准
- **市场**：几乎所有 Kubernetes 发行版都预装 Helm
- **生态**：Helm Hub 有 10000+ Chart
- **应用**：被几乎所有 Kubernetes 用户使用

## 💼 应用场景

### 场景 1：部署 Web 应用

**痛点**：Web 应用需要多个 Kubernetes 资源，手动管理容易出错。

**解决方案**：用 Helm Chart 部署 Web 应用。

**具体实现**：

**创建 Chart**：
```bash
# 创建 Chart 骨架
helm create mywebapp

# 目录结构
mywebapp/
├── Chart.yaml
├── values.yaml
├── values.schema.json
├── templates/
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   ├── configmap.yaml
│   ├── secret.yaml
│   ├── serviceaccount.yaml
│   └── tests/
│       └── test-connection.yaml
├── .helmignore
├── README.md
└── charts/
```

**Chart.yaml**：
```yaml
apiVersion: v2
name: mywebapp
description: A Helm chart for Kubernetes
type: application
version: 0.1.0
appVersion: "1.0.0"
```

**values.yaml**：
```yaml
replicaCount: 2

image:
  repository: myregistry/mywebapp
  pullPolicy: IfNotPresent
  tag: "1.0.0"

nameOverride: ""
fullnameOverride: ""

serviceAccount:
  create: true
  annotations: {}
  name: ""

podAnnotations: {}

podSecurityContext:
  runAsNonRoot: true
  runAsUser: 1000
  fsGroup: 1000

securityContext:
  allowPrivilegeEscalation: false
  capabilities:
    drop:
    - ALL
  readOnlyRootFilesystem: true

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: true
  className: "nginx"
  annotations:
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
    nginx.ingress.kubernetes.io/rewrite-target: /
  hosts:
    - host: mywebapp.example.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: mywebapp-tls
      hosts:
        - mywebapp.example.com

resources:
  limits:
    cpu: 1000m
    memory: 512Mi
  requests:
    cpu: 500m
    memory: 256Mi

autoscaling:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 80
  targetMemoryUtilizationPercentage: 80

nodeSelector: {}

tolerations: []

affinity: {}

env: []
```

**部署命令**：
```bash
# 检查 Chart
helm lint ./mywebapp

# 安装 Chart
helm install mywebapp ./mywebapp

# 使用自定义配置安装
helm install mywebapp ./mywebapp --values prod-values.yaml

# 查看 Release
helm list
helm status mywebapp

# 查看 Release 的资源
helm get manifest mywebapp

# 获取 Release 的 Values
helm get values mywebapp

# 渲染模板（不安装）
helm template mywebapp ./mywebapp

# 测试 Chart（dry-run）
helm install mywebapp ./mywebapp --dry-run --debug

# 升级 Release
helm upgrade mywebapp ./mywebapp

# 回滚到上一个版本
helm rollback mywebapp

# 卸载 Release
helm uninstall mywebapp
```

**效果**：
- 📦 **一键部署**：一个命令部署完整应用
- 🔄 **版本管理**：支持升级、回滚
- 🎛️ **配置灵活**：通过 Values 定制化
- 📊 **状态追踪**：查看 Release 历史

### 场景 2：部署微服务

**痛点**：微服务架构应用，服务数量多，依赖关系复杂。

**解决方案**：用 Helm 管理微服务架构。

**具体实现**：

**项目结构**：
```
microservices/
├── charts/
│   ├── api-gateway/
│   ├── user-service/
│   ├── order-service/
│   └── product-service/
└── helmfile.yaml
```

**使用 Helmfile**：
```yaml
# helmfile.yaml
repositories:
  - name: bitnami
    url: https://charts.bitnami.com/bitnami

releases:
  # API 网关
  - name: api-gateway
    namespace: production
    chart: ./charts/api-gateway
    values:
      - ./environments/prod/api-gateway-values.yaml

  # PostgreSQL（使用 Bitnami Chart）
  - name: postgresql
    namespace: production
    chart: bitnami/postgresql
    version: "12.x.x"
    values:
      - ./environments/prod/postgresql-values.yaml

  # Redis
  - name: redis
    namespace: production
    chart: bitnami/redis
    version: "17.x.x"
    values:
      - ./environments/prod/redis-values.yaml

  # 用户服务
  - name: user-service
    namespace: production
    chart: ./charts/user-service
    needs:
      - postgresql
    values:
      - ./environments/prod/user-service-values.yaml
```

**部署命令**：
```bash
# 安装 Helmfile
helmfile install

# 同步状态
helmfile apply

# 列出所有 Release
helmfile list

# 删除所有 Release
helmfile destroy
```

**效果**：
- 🏗️ **架构即代码**：整个架构定义在一个文件中
- 🔗 **依赖管理**：自动处理服务间依赖
- 🔄 **统一部署**：一次命令部署所有服务
- 🎛️ **环境隔离**：不同环境使用不同配置

### 场景 3：创建私有 Chart 仓库

**痛点**：内部应用需要私有仓库，不能公开发布。

**解决方案**：搭建私有 Helm 仓库。

**具体实现**：

**使用 ChartMuseum**：
```yaml
# docker-compose.yml
version: '3.8'

services:
  chartmuseum:
    image: ghcr.io/helm/chartmuseum:v0.14.0
    container_name: chartmuseum
    ports:
      - "8080:8080"
    environment:
      - STORAGE=local
      - STORAGE_LOCAL_ROOTDIR=/charts
      - BASIC_AUTH_USER=admin
      - BASIC_AUTH_PASS=password
      - ALLOW_OVERWRITE=true
    volumes:
      - ./charts:/charts
      - ./chartmuseum-data:/chartmuseum-data

volumes:
  chartmuseum-data:
```

**启动 ChartMuseum**：
```bash
# 启动服务
docker-compose up -d

# 访问
curl -u admin:password http://localhost:8080/

# 打包并上传 Chart
helm package ./mychart
curl -u admin:password --data-binary @mychart-0.1.0.tgz http://localhost:8080/api/charts

# 添加仓库
helm repo add myrepo http://localhost:8080 --username admin --password password

# 搜索
helm search repo mychart

# 从私有仓库安装
helm install myapp myrepo/mychart
```

**使用 OCI 注册表**：
```bash
# Helm 3 支持 OCI 标准
# 可以使用任何 OCI 兼容的注册表（Docker Registry、GHCR、Harbor）

# 推送到 Docker Registry
helm push mychart-0.1.0.tgz oci://registry.example.com/mychart

# 推送到 GitHub Container Registry
helm push mychart-0.1.0.tgz oci://ghcr.io/myorg/mychart

# 从 OCI 注册表安装
helm install myapp oci://registry.example.com/mychart --version 0.1.0
```

**效果**：
- 🔒 **私有仓库**：内部 Chart 安全存储
- 📦 **OCI 标准**：使用容器注册表存储 Chart
- 🚀 **快速分发**：像镜像一样推送和拉取
- 🎛️ **Web UI**：Harbor 提供可视化界面

### 场景 4：生产环境最佳实践

**痛点**：生产环境需要完善的配置管理和安全策略。

**解决方案**：使用 Helm 的生产最佳实践。

**具体实现**：

**1. Secrets 管理**：
```yaml
# 不要把敏感信息放在 values.yaml 中
# 使用 Kubernetes Secrets 或外部密钥管理

# templates/secret.yaml
{{- if .Values.existingSecret }}
# 使用已存在的 Secret
apiVersion: v1
kind: Secret
type: Opaque
metadata:
  name: {{ .Values.existingSecret }}
data:
  {{- range $key, $value := .Values.secretData }}
  {{ $key }}: {{ $value | b64enc }}
  {{- end }}
{{- else }}
# 创建新的 Secret
apiVersion: v1
kind: Secret
type: Opaque
metadata:
  name: {{ include "myapp.fullname" . }}
stringData:
  {{- range $key, $value := .Values.secretData }}
  {{ $key }}: {{ $value | quote }}
  {{- end }}
{{- end }}
```

**2. 环境配置**：
```yaml
# environments/prod/values.yaml
replicaCount: 3

image:
  tag: "2.0.0"

resources:
  limits:
    cpu: 2000m
    memory: 1Gi
  requests:
    cpu: 1000m
    memory: 512Mi

autoscaling:
  enabled: true
  minReplicas: 3
  maxReplicas: 20

ingress:
  enabled: true
  annotations:
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
    nginx.ingress.kubernetes.io/rate-limit: "100"

podDisruptionBudget:
  enabled: true
  minAvailable: 2

nodeSelector:
  environment: production

tolerations:
  - key: workload
    operator: Equal
    value: production
    effect: NoSchedule
```

**3. Pod 中断预算**：
```yaml
# templates/pdb.yaml
{{- if .Values.podDisruptionBudget.enabled }}
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: {{ include "myapp.fullname" . }}
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
spec:
  {{- if .Values.podDisruptionBudget.minAvailable }}
  minAvailable: {{ .Values.podDisruptionBudget.minAvailable }}
  {{- end }}
  {{- if .Values.podDisruptionBudget.maxUnavailable }}
  maxUnavailable: {{ .Values.podDisruptionBudget.maxUnavailable }}
  {{- end }}
  selector:
    matchLabels:
      {{- include "myapp.selectorLabels" . | nindent 6 }}
{{- end }}
```

**4. 持续集成**：
```bash
#!/bin/bash
# ci/deploy.sh

set -e

NAMESPACE=${1:-production}
CHART_PATH="./charts/myapp"
VALUES_PATH="./environments/${NAMESPACE}/values.yaml"
HELM_RELEASE="myapp-${NAMESPACE}"

# 构建 Docker 镜像
IMAGE_TAG=$(git rev-parse --short HEAD)
docker build -t myregistry/myapp:${IMAGE_TAG} .
docker push myregistry/myapp:${IMAGE_TAG}

# 更新 values.yaml 中的镜像 tag
sed -i.bak "s|tag:.*|tag: \"${IMAGE_TAG}\"|" ${VALUES_PATH}

# Helm lint
helm lint ${CHART_PATH}

# 部署到测试环境
helm upgrade --install myapp-test ${CHART_PATH} \
  --namespace test \
  --values ./environments/test/values.yaml \
  --set image.tag=${IMAGE_TAG} \
  --wait \
  --timeout 5m

# 运行测试
./scripts/run-tests.sh

# 部署到生产环境
if [ "$NAMESPACE" = "production" ]; then
  helm upgrade --install ${HELM_RELEASE} ${CHART_PATH} \
    --namespace ${NAMESPACE} \
    --values ${VALUES_PATH} \
    --set image.tag=${IMAGE_TAG} \
    --wait \
    --timeout 10m \
    --atomic \
    --cleanup-on-fail
  
  helm status ${HELM_RELEASE} -n ${NAMESPACE}
  helm history ${HELM_RELEASE} -n ${NAMESPACE}
fi
```

**效果**：
- 🔒 **安全配置**：敏感信息外部管理
- 🎯 **环境隔离**：不同环境独立配置
- 🛡️ **高可用**：PDB 保证最小可用副本
- 🔄 **自动化部署**：CI/CD 集成

## 🔧 工具与生态

### 核心命令

| 命令 | 用途 | 示例 |
|------|------|------|
| `helm create` | 创建 Chart | `helm create mychart` |
| `helm lint` | 检查 Chart | `helm lint ./mychart` |
| `helm install` | 安装 Release | `helm install myapp ./mychart` |
| `helm upgrade` | 升级 Release | `helm upgrade myapp ./mychart` |
| `helm uninstall` | 卸载 Release | `helm uninstall myapp` |
| `helm list` | 列出 Release | `helm list -A` |
| `helm status` | 查看 Release 状态 | `helm status myapp` |
| `helm rollback` | 回滚 Release | `helm rollback myapp 2` |
| `helm get values` | 获取 Values | `helm get values myapp` |
| `helm repo add` | 添加仓库 | `helm repo add stable https://charts.helm.sh/stable` |
| `helm search` | 搜索 Chart | `helm search repo nginx` |
| `helm pull` | 下载 Chart | `helm pull bitnami/nginx` |
| `helm show` | 查看 Chart 信息 | `helm show bitnami/nginx` |

### Helm 插件

- **Helm Diff**：显示升级差异
- **Helm Secrets**：加密敏感信息
- **Helm Git**：从 Git 仓库安装
- **Helm S3**：从 S3 安装 Chart
- **Helm File**：从本地文件系统安装

**安装插件**：
```bash
# 安装 Helm Diff
helm plugin install https://github.com/databus23/helm-diff

# 使用 Helm Diff
helm diff upgrade myapp ./myapp

# 安装 Helm Secrets
helm plugin install https://github.com/jkroepke/helm-secrets

# 使用 Helm Secrets
helm secrets install myapp ./myapp --values ./secrets.yaml
```

### Chart 开发工具

- **Helm unittest**：Chart 单元测试
- **Helm Chart Testing**：Chart 集成测试
- **Kubeval**：Kubernetes YAML 验证
- **Yamllint**：YAML 语法检查

```bash
# 安装 helm unittest
helm plugin install https://github.com/quintush/helm-unittest

# 运行测试
helm unittest mychart

# 使用 kubeval 验证
helm template myapp ./myapp | kubeval
```

## ⚖️ 优缺点分析

| 维度 | ✅ 优点 | ❌ 缺点/局限性 |
|------|---------|---------------|
| **易用性** | 简化复杂应用部署 | 模板语法需要学习 |
| **可重用性** | Chart 可重复使用 | Chart 质量参差不齐 |
| **版本管理** | 完善的版本控制 | 版本兼容性需注意 |
| **配置管理** | Values 灵活配置 | 复杂配置难以管理 |
| **生态系统** | Helm Hub 有丰富 Chart | 官方 Stable 仓库已弃用 |
| **安全性** | 支持密钥管理 | 敏感信息容易泄露 |
| **学习成本** | ⭐⭐⭐☆☆（2-4周上手） | Go 模板语法学习曲线 |
| **适用场景** | 几乎所有 Kubernetes 应用 | 简单应用可能过于复杂 |
| **社区活跃度** | 非常活跃 | 工具碎片化 |
| **企业级功能** | 支持企业级功能 | 需要额外配置 |

## 👥 适合谁学？

### ✅ 强烈推荐

- **Kubernetes 用户**：几乎所有 K8s 用户都用到 Helm
- **DevOps 工程师**：负责应用部署和管理
- **SRE**：站点可靠性工程师
- **云架构师**：设计云原生应用架构
- **后端开发**：了解应用如何部署

### ⚠️ 了解即可

- **前端开发**：了解部署方式
- **测试工程师**：了解环境搭建
- **项目经理**：了解部署流程

### ❌ 可能用不到

- 非 Kubernetes 用户
- 纯本地部署

### 📊 学习曲线

**⭐⭐⭐☆☆（2-4周上手）**

| 阶段 | 时间 | 能达到的水平 |
|------|------|-------------|
| 入门 | 1-2周 | 理解基本概念，会安装 Chart |
| 熟练 | 2-3周 | 会创建简单 Chart，会定制化 |
| 精通 | 1-2月 | 会创建复杂 Chart，会调试 |
| 专家 | 3月+ | 深入理解底层，贡献代码 |
